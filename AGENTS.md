# PB3 — правила проекта для всех агентов

Единый источник правил для Claude Code и Codex. `CLAUDE.md` подключает этот
файл; скилы лежат в `.claude/skills/` и видны Codex через ссылки в
`.agents/skills/`. Правило меняется только здесь, не дублируется.

## Проект

Godot-порт Power Blade 2 + Tokkyuu Shirei Solbrain (PB3): два героя — Нова
(PB2) и Солбрайн — на уровнях обеих игр, один или вдвоём. Личный проект,
не работа Attract Group. Документация — на русском.

## Скилы

- `godot` (`.claude/skills/godot/SKILL.md`) — читать перед ЛЮБЫМ изменением
  в `game/`, `work/extract/`, `work/tools/`. Там же правила приёмки прохождений.
- `pb3-pixel-animation` (`.claude/skills/pb3-pixel-animation/SKILL.md`) —
  новые и переделанные анимации героев в Aseprite.

## Проверки и приёмка

- Уровень «пройден» только по записи обычных нажатий от штатного входа до
  штатного выхода/победы (`game/tests/playthrough.gd`). Телепорт, бессмертие,
  прямой вызов перехода не засчитываются. Чек-лист:
  `docs/qa/playthrough-checklist.md`.
- Тест считается пройденным только при коде выхода 0 И без `SCRIPT ERROR` в
  выводе Godot.
- Поведение оригинала сверять с картриджем (`work/tools/nesemu`, дизассемблер),
  а не придумывать. Правила объединения двух игр, которых нет ни в одном
  картридже, не изобретать молча.

## Баги и вопросы

- Каждый найденный баг — запись в документацию (ID, уровень, герой, нажатия /
  тик, ожидаемое, наблюдаемое, причина, исправление, проверка), затем
  исправление и отдельный коммит сразу после проверки.
- Где нужно решение человека (баланс, совмещение механик двух игр) — не
  угадывать: добавить вопрос в `docs/pb3-gameplay-questions.md` (формат GAP-xx)
  с вариантами, продолжать работу без этой механики.

## Git

- Коммитить только свои файлы явными путями (`git add <путь>`), никогда
  `git add -A` / `git commit -a`: в дереве бывают чужие незавершённые правки.
- Один исправленный баг — один коммит; в сообщении ID бага.
- Файлы с `class_name`, их `.uid` и `game/.godot/global_script_class_cache.cfg`
  коммитить вместе.
