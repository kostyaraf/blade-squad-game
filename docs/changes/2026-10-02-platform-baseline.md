# Исходное состояние аудита стыков — eb78205

## Что уже представляет собой продукт

Три режима: самостоятельные Power Blade 2 и Solbrain, а также PB3 с выбором
любого из двух героев на любом из 83 входов. PB3 допускает одного/двух игроков;
ввод поступает в `Pb3Session.advance(frame, words)`. Онлайн не реализован.
Визуализация и устройства ввода находятся вне этой последовательности шагов.

Родная физика остаётся в `Pb2Player`/`SolPlayer`, данные извлечены из NES.
`Pb2AsSol` и `SolAsPb2` переводят поверхность; `Pb3Pair` связывает координаты,
камеру, контактные тела и оружие. `Pb3Draw` собирает две таблицы спрайтов.
`Pb3Gear` хранит выбор снаряжения и общую энергию, но не все игровые записи
ресурсов пока проходят через него. Это существующий разрыв ответственности.

Уже подтверждено десять записей прохождений, а не вся игра. Полное закрытие
каждого входа и составов отражается только в `docs/qa/playthrough-checklist.md`.

## Проверяемые правила интеграции

Эти технические условия следуют из существующего продукта и не заменяют
нерешённые вопросы баланса:

1. Один такт сессии изменяет мир один раз. Отрисовка читает результат и не
   создаёт второй независимый таймер симуляции.
2. Уровень один для всех участников. Разрушение, фоновая фаза, опасности и
   движущиеся объекты имеют одно состояние.
3. Адаптер сохраняет отдельные свойства: твёрдость, опасность, движение
   поверхности, вода. Совпадение номера/бита двух разных игр ничего не доказывает.
4. Любое личное воздействие относится к конкретному игроку, даже если для
   контакта используется временное представление героя в другой игре.
5. Доступный выбор костюма/оружия относится к выбравшему игроку. Состояние
   первого героя не может отменять способность второго.
6. Для общего ресурса нужен один владелец состояния. Копия для родного
   алгоритма должна возвращать изменения, а не перезаписывать их следующим кадром.
7. У проверки должен быть реально исполненный непустой сценарий. Пустая
   трасса, ноль шагов или только проверка импорта не подтверждают игровое поведение.

## Стартовые кандидаты

| ID | Граница | Наблюдение на старте | Статус |
|---|---|---|---|
| INT-01 | Проверка ↔ эмулятор | Два стенда задают конечный кадр раньше сохранённого; возможна ложная успешная сверка неподвижных таблиц | Подтверждено чтением вызовов; нужен исправленный прогон |
| INT-02 | Поверхности Solbrain → Nova | `$16/$17` превращаются в обычный пол, `$0E/$0F` названы лентами без сохранения родной семантики | Подтверждено кодом; нужны реальные клетки/движение |
| INT-03 | Контакт ↔ владелец снаряжения | `_wound_hero(hero)` проверяет глобальный `suit` пула вместо костюма переданного героя | Кандидат; нужен сценарий с перестановкой игроков |
| INT-04 | Награда ↔ сессия | `_pick_up` пишет в `host_status`, а `_sync_gear` копирует меню обратно | Кандидат; технические потери отделить от GAP-01/04/06/07 |

Основание: исходники на `eb78205`, предыдущий отчёт окружения и запрос
пользователя на поиск повторяющихся дефектов. Непроверенные кандидаты не
считаются исправленными. Полная смена движков на одну физику не требуется
для устранения этих ошибок и не принимается здесь как продуктовое решение.
