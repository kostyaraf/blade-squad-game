# Звук PB3

Причины тишины:

- PB3 выбирал драйвер уровня, но не заказывал музыку при входе.
- Запросы эффектов другой игры не получали свой драйвер.
- SndPlay сбрасывал APU, но не выполнял инициализацию каналов из reset-кода
  картриджа: PB2 `$E5DA`, Solbrain `$F911`. Без `$4015` каналы отключены.
- Записи регистров от прямого `ask()` терялись перед очередным tick.

Исправление: стартовые записи извлекает `work/extract/sound.py`; SndPlay
применяет их к чипу и сохраняет записи до следующего tick. PB3 воспроизводит
музыку и эффекты уровня через его драйвер, эффекты другого героя — через
второй независимый драйвер. Это правило смешанного режима, которого нет на NES.
Для двух выходов оставлен запас громкости по 6 dB. При возврате к списку
уровней очищаются драйверы и уже подготовленные звуковые буферы.

Музыка Solbrain берётся из `music` записи уровня (ROM `$E776`), Power Blade 2 —
из существующих правил Pb2Flow для этапов, специальных комнат и боссов.

Проверка живой сцены: `game/tests/pb3_audio_test.gd`. Обычный ввод контроллера
проходит через `main._step`; проверяются PCM музыки и атак каждого героя на
обоих типах уровней, кооператив, выбор трека для всех 83 входов и очистка при
возврате к списку. Начальный переходный процесс фильтров исключён из измерения,
чтобы одиночный щелчок при включении не засчитывался как музыка.

Сверка драйверов: `verify_sound.py` — 202 сценария, 51 240 кадров, ноль
расхождений команд с картриджами. `verify_pb3_playthrough.py` — семь записанных
прохождений без регрессий. Предупреждение ObjectDB при выходе интеграционного
стенда остаётся известной отдельной проблемой.

`verify_snd_play.py`: все 38 проверок количества циклов и сэмплов прошли.
Итоговый интеграционный прогон: 0 ошибок; без чужого персонажа второй выход
остаётся тихим после начального переходного процесса.
