# Проверка PB3 на физическом Switch

## SW-02 — повреждённая графика заставки и первого уровня PB2

- Источник: сообщение и два снимка пользователя от 4 октября 2026;
  Switch с Кефиром, запуск PB3 из Sphaira. Версии прошивки и Sphaira
  пока неизвестны. Сборка из выданного в чате PB3-Switch-Kefir.zip;
  хеши файлов на SD не сверены.
- Уровень: заставка Power Blade 2 и первый уровень. Герой — Нова;
  точные кнопки и тик пользователь не записал.
- Воспроизведение: открыть PB3.nro из Sphaira, выбрать Power Blade 2,
  перейти от заставки к первому уровню обычными кнопками.
- Ожидаемое: правильные тайлы фона, герой и читаемые надписи.
- Наблюдаемое: длительный чёрный экран, затем посторонние тайлы;
  нижняя панель содержит «DEDF», «BBDD» вместо штатных надписей.
- Причина графики: данные номеров тайлов и OAM передавались как RGBA8.
  GLES3 Homebrodot может выделять для них GL_SRGB8_ALPHA8 при наличии
  EXT_texture_sRGB_decode, даже при флагах текстуры 0. Чтение texelFetch
  на драйвере, декодирующем sRGB, меняет RGB-байты и номера тайлов.
  На Mac принудительное декодирование RGB только map/bar/oam/oam2
  воспроизвело характерную картинку и те же повреждённые надписи.
  Чёрный экран при загрузке этой проверкой не объяснён.
- Исправление: только в адаптере Switch при загрузке и обновлении RGBA8
  создаётся отдельное изображение RGBAF. Оно хранится как GL_RGBA32F,
  для которого нет преобразования sRGB. Изображения игровой логики
  остаются в прежнем формате; R8-листы тайлов не меняются.
- Проверка: GPU-тест всех 256 значений каждого из четырёх каналов,
  включая обновление текстуры, прошёл с кодом 0 без SCRIPT/SHADER ERROR.
  Снимок первого уровня PB2 после исправления точно совпал по RGB
  с правильной настольной картинкой до исправления. PB2, Solbrain, PB3
  и заставка PB2 запущены на Mac, код 0 без SCRIPT/SHADER ERROR.
- Статус: исправление проверено на Mac; на Switch требуется повторный
  запуск обновлённого PCK. Полные прохождения этим не подтверждены.

## SW-03 — удалённые методы стартового экрана Solbrain

- Уровень, герой: штатный запуск Solbrain из общего меню; герой ещё
  не выбран. Ввод: выбор Solbrain, затем 180 кадров без нажатий.
- Ожидаемое: стартовый экран выполняет штатную логику без ошибок.
- Наблюдаемое: SCRIPT ERROR в SolFlow._no_sprites и _title_wait:
  у main.gd отсутствуют flow_table и flow_pad_new. Процесс возвращает
  код 0, но из-за SCRIPT ERROR проверка считается проваленной.
- Причина: конвертер сохранял методы main.gd только по внутренним
  ссылкам с префиксом «_». Методы flow_* вызываются из SolFlow через
  переданный объект, поэтому ошибочно считались недостижимыми.
- Исправление: все методы flow_* сохранены как публичные точки входа;
  их внутренние зависимости также сохраняются штатным обходом.
- Проверка: запуск из общего меню в режиме sol-title, 180 кадров без
  нажатий, код 0, без SCRIPT ERROR и SHADER ERROR. Проверено на Mac;
  запуск этого исправления на Switch ещё не подтверждён.

## SW-04 — около 1 FPS и прерывистый звук на Switch

- Источник: пользователь проверил 0.1.1 на Switch с Кефиром.
- Уровень, герой: запуск/игра Power Blade 2, Нова; точный тик и ввод
  не записаны. Ожидание: игра работает с обычной скоростью и непрерывным
  звуком. Наблюдение: примерно 1 FPS, провалы звука примерно каждые 0.5 с.
- Причина: выясняется. Шейдер перебирает до 64 спрайтов для каждого
  пикселя каждого активного OAM; GDScript синтезирует звук на главном
  потоке. Генератор имеет запас лишь 0.08 с; при секундных задержках
  воспроизведение не может быть непрерывным.
- Исправление: OAM подготовлен как очередь первых восьми спрайтов для
  каждой видимой строки. GPU теперь проверяет до 8, а не 64 записей
  каждого активного OAM на пиксель, сохраняя ограничение и порядок NES.
  В APU применены точные переходы LFSR, быстрый пропуск пустого DMC,
  кэш расстояния до события кадра и раскрытие горячих мелких функций.
  Частота сэмплов и игровая физика не изменены.
- Проверка: 3840 строк случайного OAM и перегруженных строк совпали
  с отбором из исходных 64 записей. RGB-кадры PB2, Solbrain, PB3 и
  смешанной пары совпали с прежним шейдером. Синтез сравнен с исходным
  Godot 3: 160 интервалов, случайные записи всех регистров, 129654 сэмпла;
  расхождений байтов и состояния нет. Все проверки: код 0, без
  SCRIPT ERROR/SHADER ERROR.
- Настольный CPU-замер первого уровня PB2: 12.72 мс на синтез одного
  шага до оптимизации и около 6.8 мс после (Mac M1 Pro, Godot 3 через
  Rosetta). Это не замер FPS Switch и не обещание 60 FPS на консоли.
- Диагностика: каждые 5 с на Switch сохраняются последние интервалы
  FPS, времени главного потока и пропусков аудио в user://switch-perf.json.
  На Mac формат файла и запись проверены отдельным запуском с флагом
  --switch-perf; viewport 256x240.
- Статус: новая версия требует проверки на Switch. Первоначальная
  задержка GPU и реальная производительность измерениями с консоли
  пока не установлены. Не считать SW-04 закрытым до повторной проверки.

## SW-05 — невидимое меню выбора игры на Switch

- Источник: тот же запуск 0.1.1. Ожидание: видимые Power Blade 2,
  Solbrain и Power Blade 3, затем выбор состава для PB3.
- Наблюдение: чёрный экран; после случайных нажатий запускается PB2.
  Это согласуется с невидимым, но работающим первым выбранным пунктом.
- Причина: выясняется. Меню использует WOFF2 через DynamicFont, фон
  с NES-шейдером остаётся активен. Ни загрузка WOFF2 на консоли, ни время
  первого кадра меню прежней настольной проверкой не подтверждены.
- Исправление: меню использует обычный TTF Noto Sans вместо WOFF2;
  NES-фон скрыт при выборе игры и в списке PB3, синтез неиспользуемого
  звука в этих меню остановлен. Причина отсутствия WOFF2 на устройстве
  остаётся гипотезой; заменой убрана эта зависимость.
- Проверка: menu_probe.gd прошёл 90 кадров обычного ввода вниз/вниз/Start,
  проверил три пункта, ширину букв, отсутствие NES-фона и выбор PB3;
  код 0, без SCRIPT ERROR/SHADER ERROR. Сохранены снимки обоих меню.
  Повторная проверка на Switch ещё нужна.
