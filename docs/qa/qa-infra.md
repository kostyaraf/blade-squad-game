# QA-инфраструктура: регрессия одной командой и робот-разведчик

Ноябрь 2026, ветка `dev/qa-infra`.

## Регрессия одной командой

```
python3 work/qa/run_all.py            # всё, не больше 2 Godot одновременно
python3 work/qa/run_all.py --list     # какие проверки есть
python3 work/qa/run_all.py --only=replay,pb3_combat
python3 work/qa/run_all.py --smoke    # + короткий проход разведчика
python3 work/qa/run_all.py --oracle   # + стенды со сверкой по картриджу (долго)
```

Что входит: повтор всех принятых прохождений (`docs/qa/playthrough/cases.json`,
проверка `replay`) и все `game/tests/*_test.gd`, которым не нужны данные
эмулятора. Графические проверки (`pb3_display`, `pb3_geometry`) идут с
окном — им нужен настоящий кадр. Проверка провалена, если код выхода не 0,
вышло время или в выводе есть `SCRIPT ERROR` / `SHADER ERROR` / `Parse Error`.
Полный вывод каждой проверки — во временном файле `$TMPDIR/pb3-qa/<имя>.log`,
он удаляется, если проверка прошла. На экран — одна строка на провал и
итог «N of M checks failed». Логи Godot в файлы не пишутся
(`project.godot`).

Не входят по умолчанию: стенды, которые сначала гоняют сцену на картридже
(`pb2_death`, `pb2_small_shots`, `pb2_hand_4a`, `pb2_nest_1c`,
`pb2_nest_child_1c`, `pb2_pod_33`, `pb2_raster_kind4`, `pb3_environment`,
`sol_pickups`) и сверка движения Новы `verify_player.py` — их запускает
`--oracle`. Без входных данных эти тесты не выходят сами, а висят.
`pb3_visual_test.gd` — не проверка, а снимки экрана в `docs/qa/`.

## Робот-разведчик

```
python3 work/qa/smoke.py                         # 83 уровня × Нова, Солбрайн, вдвоём
python3 work/qa/smoke.py --levels=p1.0,s3.0 --teams=nova --ticks=6000 --seed=7
python3 work/qa/smoke.py --repro=p1.0:nova:1 --ticks=4000 --trace=21
```

Каждый уровень открывается штатным входом списка уровней, дальше только
нажатия (`Pb3Session.advance`): никаких переносов, бессмертия и правки
состояния. Нажатия детерминированы: зерно прогона = хеш(зерно, уровень,
команда). Поведение: идти к дальнему краю уровня с ударами; если позиция не
меняется — прыжок, длинный прыжок, вверх по лестнице, вниз, затем
развернуться; вперемешку случайные серии кнопок (без START/SELECT).

Что считается аномалией:

| Вид | Условие |
|---|---|
| `script_error`, `engine_error` | ошибка Godot во время шага (перехват через `Logger`) |
| `crash`, `hang` | процесс Godot упал или завис на этом прогоне |
| `out_of_level` | ноги героя вне карты дольше 10 кадров |
| `inside_solid` | герой внутри твёрдой клетки дольше 30 кадров |
| `camera_lost` | живой герой за краем экрана дольше 45 кадров |
| `stuck` | 600 кадров без сдвига на 2+ px, хотя жали и влево, и вправо |
| `bad_health` | здоровье вне 0..16 (Нова) / 0..8 (Солбрайн) |
| `missing_handler` | объект без перенесённого обработчика |
| `object_out_of_level` | объект Solbrain далеко за картой |
| `held_forever`, `frozen` | игра стоит 1200 / 900 кадров |
| `slow_step` | один шаг дольше 100 мс |
| `early_death` | команда погибла в первые 120 кадров |

Отчёт: `$TMPDIR/pb3-smoke/smoke.md` (кратко, с командой повтора) и
`smoke.json`; для прогонов с аномалиями — запись в формате
`playthrough.gd` в `replays/`. Найденное роботом — повод разобраться, а не
доказательство: каждую аномалию надо повторить и отделить настоящий баг от
особенности робота.

## Найденные ошибки

### QAI-01 — p3.6 (и p1.0, p1.5): неверная начальная линия лавы/воды

- Уровень / герой: p3.6 (Power Blade 2 — 4, комната 7), Нова; также p1.0 и p1.5.
- Нажатия / тик: любые; разведчик, зерно 1 (`--repro=p3.6:nova:1`), смерть на 1-м кадре.
- Ожидаемое: на картридже (эмулятор, вход через $53/$9C) герой стоит на
  поднимающемся полу лавы: в первом игровом кадре линия $29 = 142, ноги на 143.
- Наблюдаемое: Нова погибал сразу после входа, Солбрайн «застревал».
- Причина: `pb2_area_kind.py` читал $29/$20/$FC/$87 на кадре IN_LEVEL+2,
  через ~360 кадров игры после открытия участка. За это время линия уже
  сдвинулась (p3.6: 142 → 113, p1.0: 47 → 105, p1.5: 142 → 135), и герой
  оказывался на 29 строк под полом лавы — правило $B5E7 давило его.
- Исправление: экстрактор читает значения в первом кадре, когда участок
  играется ($1A = 5 и герой поставлен); данные перегенерированы. Смысловые
  изменения только у p1.0, p1.5, p3.6 (вид 0/1/2 и draw в других участках на
  движок не влияют).
- Проверка: разведчик — p3.6 Нова/Солбрайн/вдвоём живут 1300–2400 кадров
  вместо 1; сверка с картриджем p1.5 (смерть в лаве при ходьбе влево на 44-м
  кадре совпадает с движком). **Полная регрессия после правки не завершена**
  (остановлено по команде). Вероятно, разойдутся записи, проходящие через
  p1.0 (`p1-nova-pb2b*`): они сделаны при неверной линии.
