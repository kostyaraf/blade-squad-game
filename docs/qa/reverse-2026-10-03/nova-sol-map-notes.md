этот документ не подтверждает прохождения. Применены skills `laconic-answers`,

## Обязательные сценарии

- s1: шахта x1792…2047 ведёт вниз от y256…511 к y1024…1279; это
  вертикальная геометрия с уступами/опасностями. `$A835/$A867` раскрывают
  камеру по мере спуска. Не путать с авто-лифтом следующего s2.
- s2: после подхода к шахте `$A8EB` заводит `map_kind=$3C`, `fall=8` через
  `$AA46`. Камера автоматически едет вверх, опору родной герой получает
  из линии `$75*16` относительно камеры (`$D035`). `$A9C6` останавливает
  подъём в районе y1024 и проводит последующий цикл движения лифта.
  Проверить, что Нова действительно стоит на динамической линии: его
  `SolAsPb2.class_byte()` читает только `SolLevel.collision_at()`, поэтому
  по статике специальная опора может отсутствовать. Это гипотеза, не баг ID.
- s7: пять скриптов промежуточных боссов идут по `$57`: комнаты (3,4),
  (6,4), (6,5), (4,5), (3,6). Колонки начала: x992…1007,1568…1583,
  1552…1567,976…991,992…1007. Нельзя считать маршрут закрытым, просто
  добежав до правого конца: последовательность задаёт сам скрипт.
- s15: промежуточные сценарии боссов в (3,7), (5,9), (10,6).
  `$9B99` при camera.x=2816 меняет `$55=16`, а `$9CE5` делает ту же
  замену после третьей арены. Здесь нет mode `$35/$40`, поэтому штатный
  `session.resolve()` не порождает `changed`. Следить за `host_sol.stage`
  и реальной заменой таблиц карты: общий `SolLevel` может остаться stage15
  (статическая гипотеза). После замены нужна лестница уступов по x3072…3327
  вверх от y1536 до y256, а не дальнейшая ходьба по row6.

## Коллизии и границы проверки

Проверять **показанный** метатайл: при `props&$20` целая клетка использует
`alt[m]`; после разрушения — raw `m`. У разрушения одна маска на номер
метатайла, поэтому изменение повторяющихся клеток само по себе штатно.

| Класс (`props&$1F`) | Назначение по родному коду / адаптеру Новы |
|---|---|
| $00 | Воздух |
| $04 | Второй нетвёрдый класс; не PB2-лестница |
| $08 | Нетвёрдая опасность |
| $0C…$0F | Неопасные среды: $0D вода, $0E течение, $0F выход из воды |
| $10…$1F | Твёрдо; $18 содержит признак урона |
| $16/$17 | Твёрдый конвейер вправо/влево; для Новы перевод в PB2 $87/$88 |

Для Новы `hurts_at()` применяет родной классификатор Solbrain:
`(c&8)!=0 and (c&$1C)!=$0C`; это урон с паузой, не мгновенная смерть PB2.
`SolAsPb2` не создаёт лестниц из Solbrain-клеток. Вода поддерживается;
течение/лёд остаются GAP-12. Зацеп за сетку здесь не разрабатывался.

Ящики/бонусные кубы ломает родной `$B933/$B9CD`: raw property младшими
пятью битами `<$0C`, младшими двумя 2 или 3. Остальные разрушаемые ящики
могут ломаться взрывами противников по `$BE0F`, что не означает возможность
сломать их обычным бумерангом. Нельзя заменять эти два правила одним.
Награды букв/монет для Новы не утверждены: GAP-02/03/07.
