## Дефекты

### NSB-01 — переход s3 → s9 ставит Нову внутрь пола

- Уровень/герой: s3 → s9, Нова 0, костюм 1.
- Ввод: `s3-s9-nova-spawn-before/replay.json`, переход на 2476; после конца команды тик 2508, RIGHT 60 тиков (2509…2568), затем RIGHT+A 30 и RIGHT 60.
- Ожидаемое: Нова появляется над опорой и может идти вправо, как при штатном запуске s9.
- Наблюдаемое: вход (368,1152), 60 RIGHT не двигают; только прыжок освобождает из пола, далее feet=1151.
- Причина: `Pb3List.enter()` поправляет поверхностный старт Новы на y−1; `Pb3Session._travel()` использует сырую `two.home()` без той же коррекции.
- Исправление: общий `Pb3List.entry_spots()` для старта из меню и для `_travel()`. Техническое согласование двух путей одного входа, не новое правило способностей.
- Проверка: `pb3_sol_exits_test.gd` (все s0…s19 × 6 составов: вход через переход = вход из меню) — 0 из 280, код 0, без SCRIPT ERROR; `pb3_session_test.gd` 0 ошибок; `verify_pb3_playthrough.py` 0 из 11. Запись после: `s3-s9-nova-spawn-after/replay.json` — 60 RIGHT после входа двигают Нову 368 → 447 (feet 1151).
- Коммит: NSB-01.

### NSB-02 — сценарная прокрутка камеры Solbrain утягивает Нову сквозь пол

- Уровень/герой: s1, Нова 0. Шахта x1792…2047 (комната (7,1)), где сценарий s1 сам опускает камеру.
- Ввод: `s1-nova-stuck/replay.json` (8010 тиков обычных нажатий); прыжок на уступ y416 около x1914 на 7864…7886.
- Ожидаемое: Нова стоит на уступе y416 (или идёт по нему), камера едет отдельно.
- Наблюдаемое: с тика 7888 камера опускается на 1 px/тик, и Нова опускается вместе с ней (y416 → 528) сквозь твёрдую колонну, затем стоит внутри стены: RIGHT/LEFT/A не действуют — тупик.
- Причина: у Новы место на экране, а не в мире; сдвиг камеры передаётся ему через `slid`. `Pb3Pair.step` считал `slid` только по `_sol_move` текущего кадра, а сценарий стадии (`SolTurn` → `script_.run`) двигает вид позже в кадре. Такой сдвиг не попадал ни в один `slid`.
- Исправление: `Pb3Pair.sol_seen` — вид, по которому герои мерились в прошлом кадре; `slid` считается от него, поэтому сценарный сдвиг передаётся в следующем кадре.
- Проверка: отладочный повтор той же записи — Нова остаётся на y416 при сдвиге камеры (slid=1/тик). Обычная запись после: `s1-nova/replay.json` — шахта пройдена, переход s1 → s2 на 4427. Тесты: `verify_pb3_playthrough.py` 0 из 18; exits 0/280, session, sol_environment 0/1467, boss_gates 0/62, combat 0/9089, surface, obstacles, contracts, geometry, hatch, sol_moves, nova_net 0/130, `verify_pb3_environment.py` 0/5987 — все код 0, без SCRIPT ERROR. `pb3_traversal_test.gd` даёт 108000 SCRIPT ERROR `guest_sol[i]` (pb3_pair.gd:735) и без этой правки — давний сбой теста, не NSB-02.
- Коммит: NSB-02.

### NSB-03 — лифт Solbrain не включается: s2/s13 без езды, Нова висит в воздухе

- Уровень/герой: s2 (шахта x768…1023, после робота id66), также s13. Нова 0, костюм 1.
- Ввод: `s2-nova-lift-before/replay.json` (1197 тиков обычных нажатий; сценарий `$A8EB` ставит `$7D=$3C` около тика 950).
- Ожидаемое: на тике после `$7D=$3C` карта становится «несущей» (`$70=$3C`): камера сама едет вверх (`$F24B`, `y -= $34`), опора — линия лифта `$75` от верха экрана (`$D035`), герой едет на ней до y1024, затем бой на лифте (`$A9C6`) и проход направо к s13.
- Наблюдаемое: `map_kind` остаётся 0 навсегда. Камера уходит вверх по обычной логике, Нова отстаёт и висит в воздухе у нижнего края экрана (y3583, sub 8) — тупик (кадр `s2-nova-lift-before/current.png`).
- Причина: два разрыва. 1) Гашение кадра (`$C3DF`: `$75 += $74`, `$C39F`: `$74 = 0`; `$FBDB`: `$70 = $7D`) было только в стенде `main.gd`, а не в `SolTurn` — общей очередности кадра Solbrain (и PB3, и одиночной игры). 2) Адаптер `SolAsPb2` (карта Solbrain для героя PB2) не знал линии лифта: на несущей карте у него нет опоры, и при сдвиге линии/камеры Нову ничто не несёт.
- Исправление: `SolTurn.blanking()` в конце кадра (`$C3DF/$C39F/$FBDB`). `SolAsPb2.ride_line` — линия лифта в пикселях уровня (её ставит `Pb3Pair._led_by_sol`): на несущей карте всё ниже линии твёрдое, стен/потолка/воды/сетки/шипов нет (`$D014`, `$A26E`). Правило PB3: картридж делает твёрдыми только 16 строк под линией (родному герою ниже не попасть), а Нова умеет висеть под потолком и перелезать через край, поэтому для неё твёрдое всё ниже линии (без этого на тике 1394 поиска Нова повисла под линией и провалилась под лифт). `Pb3Pair`: Нова, стоящая на линии, едет вместе с ней (`push_y` = сдвиг `$75` + сдвиг камеры, `$A126`).
- Проверка: отладочный повтор — `map_kind=$3C` с тика 950, камера идёт вверх по 0.5 px/тик, Нова стоит на линии (экранная y = `$75`). Обычная запись `s2-nova/replay.json`: лифт до y1024, бой на лифте, проход вправо, переход s2 → s13 на 8414, минимум HP 11. `s13-nova` перезаписан тем же вводом: лифт на s13 теперь работает, STAGE CLEAR 1479 вместо 1529 (до правки лифт там тоже не ехал). Тесты (код 0, без SCRIPT ERROR): `verify_pb3_playthrough.py` 0 из 20; sol_long 0/100, sol_run 0/20, sol_flow 0/5, sol_test 0/397, sol_end 0/960, pb3_sol_exits, sol_moves, nova_net 0/130, pair 0/2460, session, surfaces, environment 0/5987, sol_environment, run 0/332, boss_gates, combat — 0 расхождений. `verify_sol_script.py` не запускается в этой среде (нет `base.inp` эмулятора) — не проверен; он вызывает `SolScript.step()` напрямую и `SolTurn` не использует.
- Побочный эффект: правка в `SolTurn` касается и одиночной игры Solbrain (`main.gd`): лифт s2/s13 у родного героя тоже не работал. Стенды `verify_sol_long/run/flow/test` — 0 расхождений.
- Коммит: NSB-03.

### NSB-04 — босс s7 не выходит: общая камера отменяет сценарный сдвиг вида, Нова заперта у решётки x1008

- Уровень/герой: s7 (из цепочки s6 → s7), комната `$43` (x768…1023, y1024…1279), первая из пяти комнат босса седьмой стадии (`$A426`). Нова 0. Тот же сбой у Солбрайна и у пары (тест ниже).
- Ввод: поисковая запись s6 → s7 обычными нажатиями до тика 7507 (Нова у x920, y1183), затем RIGHT+B. Отладочный повтор, не приёмка.
- Ожидаемое: когда герой встаёт в столбец `$81=$3E` (x992…1007), шаг 1 (`$A456`) выпускает босса, шаг 2 держит героя, шаг 3 (`$A4BB`) сам двигает вид (`$30 += $10` за кадр), пока `$31+8 = $81`. Затем босс (`$97`) ломает решётку x1008 (метатайлы 80/83), `$57` → 1, путь вправо открыт.
- Наблюдаемое: шаг 3 не кончается: `$31` всё время `$30`, `$7F=2`. Решётка x1008 остаётся твёрдой (`$10`) сколько угодно кадров — тупик, s7 не пройти.
- Причина: `Pb3Pair._drive_view` в каждом кадре тянет вид к рамке вокруг героев (`SOL_BAND_X`) и до `x_end` комнаты. Родная камера идёт только за движущимся героем (`$F1EA`), а удерживаемый сценарием герой стоит, поэтому сдвиг сценария сохраняется. В PB3 он откатывался в следующем кадре.
- Исправление: пока сценарий держит героев (`controls_locked`, `$9E73`), общая камера Solbrain не правит вид — вид ведёт сценарий.
- Проверка: новый `game/tests/pb3_sol_boss_walk_test.gd` (Нова, Солбрайн, Нова+Солбрайн, поставлены в столбец `$3E`): до правки 6 из 6 провалов (вид не идёт, решётка цела), после — 0. Отладочный повтор: `$31` 30 → 36, босс выпущен, решётка открыта (класс 1), `$57=1` на 7927, Нова проходит в комнаты `$44`/`$45`. ### NSB-05 — после победы над боссом s17 игра замирает: Нова висит на стене под удержанием сценария

- Уровень/герой: s17, комната босса (`$AA6E`, вид x0xC000, y0x6000), Нова 0, костюм 1.
- Ввод: поисковая запись s17 обычными нажатиями; Нова зацепилась за стену x3290, y1661 (`SUB_WALL`), босс (id 65) добит тапами UP+B около тика 5100. Отладочный повтор, не приёмка.
- Ожидаемое: после босса `$AAA3` → `$9355`: шаг `$9371` держит героя (`$9E73` забирает `$04/$06`) и ждёт `$05A2` = 0 или 8 (герой на ногах), затем `$9385` (пауза) и `$9398` (затемнение, выход со стадии).

- Исправление: `Pb3Pair._let_go_held()` — пока сценарий держит героев, герой PB2 на стене/потолке/сетке отпускается (`_step_off(0)`, обычное падение) и встаёт на пол, который ждёт сценарий.
