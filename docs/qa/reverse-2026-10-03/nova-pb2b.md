## Дефекты

**NPB2-01 — неверный босс при отдельном входе p6.7–p6.9 (воспроизведён).**
Герой Нова. Ввод штатного обхода, первый вызов объекта `$06`: во всех четырёх
p6.6–p6.9 появляется `$56`. Ожидаются `$56/$57/$58/$59` соответственно.
ROM: банк 10 `$84FE` сохраняет `$53`, назначая комнату `$53+6`; `$87C3`
создаёт тип `$56+$53`. `verify_spawns.py` описывает оба регистра.
Причина: `Pb3Pair._init` всегда задаёт `came=0` для таблицы боссов;
отдельный вход теряет исходный этап, а непрерывный переход его сохраняет.
Исправлено: отдельный вход восстанавливает `$53` по номеру комнаты и `$79=1`.
Повтор с начала p6.7/p6.8/p6.9 тем же вводом: создаются `$57/$58/$59`;
записи `p6.7-nova-pb2b-entry-fixed` … `p6.9-nova-pb2b-entry-fixed`.
Фокусный `npb2_boss_entry_test.gd`: 0 ошибок, exit 0, без SCRIPT ERROR.
`verify_pb3_playthrough.py`: 23/23 записей прошли, exit 0, без SCRIPT ERROR.
Коммит: `NPB2-01: восстановить исходный этап и флаг при входе к боссу`.

Непрерывные цепочки этим дефектом не затронуты. Известный NPB-02 (Claude): отсутствующий
обработчик `$4A` в p6.2; проверка боя остаётся открытой.

**NPB2-02 — стенд падает на оставшейся команде продолжения.**
Нова, сохранённая p1.2, тик5122. Запуск playthrough.gd при command.json
с `steps`, но без `start`: ожидается ожидание нового штатного старта;
наблюдается SCRIPT ERROR на строке56 (`session.two`, session=null).
Причина: почтовый ящик переживает процесс, игровая сессия — нет.
Исправление: до обработки продолжения без сессии команда отмечается прочитанной
и игнорируется; новая команда `start` по-прежнему создаёт штатную сессию.
Проверка: оставшаяся команда `steps:[[1,0]]`, запуск с `--quit-after 30`: exit0,
без SCRIPT ERROR. Повтор цепочки p1 — после запуска рабочего стенда.
