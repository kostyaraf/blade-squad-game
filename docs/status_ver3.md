# PB3 ver3 — состояние работ

Спека: `docs/ver3_spec.md`.  Правило приёмки: сверка с настоящей игрой, а не
мнение.

## Э0 — экстрактор и формат данных

**Готово.**

Выгружено в `game/data/`:

| что | где | объём |
|---|---|---|
| палитра консоли (64 цвета) | `nes_palette.json` | — |
| графика Power Blade 2 | `pb2/tiles.png` + `pb2/chr.json` | 8192 тайла |
| графика Solbrain | `sol/tiles.png` + `sol/chr.json` | 8192 тайла |
| уровни Power Blade 2 | `pb2/levels/stage0..6.json` | 7 этапов, 63 участка |
| уровни Solbrain | `sol/levels/stage0..19.json` | 20 этапов |

Тайлы хранятся индексами цвета 0..3, цвет назначается палитрой при отрисовке —
так же, как это делает консоль.  Это нужно, чтобы работали смена цвета костюма,
вспышка раненого врага и мигание палитр фона.

### Чем доказано

**Power Blade 2.**  Восемь кадров настоящей игры (этап 0), для каждого:
* карта тайлов, собранная из выгруженных данных, совпала с видеопамятью
  консоли — 640 из 640 тайлов и 40 из 40 байт палитровых признаков;
* картинка, нарисованная из `tiles.png` и палитр, совпала со скриншотом
  эмулятора — **0 расходящихся пикселей** вне спрайтов на всех восьми кадрах.

Проверка: `python3 work/extract/verify_pb2.py`.

**Solbrain.**  Десять кадров живой игры (этап 0, с проходом вправо), картинка
рисуется прямо из мировых координат через цепочку комната → экран → блок →
метатайл → тайл.  0 расходящихся пикселей на кадрах 3405, 3560, 3900, 4000,
4200, 4400; на остальных расхождения — спрайты (герой и враги), которые на
этом этапе ещё не рисуются.

Проверка: `python3 work/extract/verify_sol.py <дамп> <скриншот>`.

### Долги Э0

1. **12 комнат Solbrain ссылаются на списки врагов, которых нет в таблице.**
   Этапы 3 (комната 72), 5 (24, 25, 41, 57, 58), 6 (100–103), 10 (25, 102, 103).
   По этим адресам лежат не записи таблицы групп, а данные списка объектов —
   значит, правило длины таблицы разобрано не до конца.  Комнаты настоящие,
   стоят в карте этапа.  Проверить, есть ли в них враги в живой игре, при
   работе над Solbrain (Э4).  В данных помечено полем `object_groups_unread`.
2. **Проверка покрывает только этап 0 обеих игр.**  Остальные этапы выгружены,
   но не сверены с живой игрой — нужен переход по этапам (варп), который пока
   не сделан для оригинальных картриджей.
3. **Спрайты не выгружены.**  Таблицы метаспрайтов героя, врагов и снарядов
   разобраны в `work/re/`, но в `game/data/` ещё не лежат — они пойдут вместе
   с работой над персонажем (Э2) и объектами (Э3).
