## Э0 — экстрактор и формат данных

Выгружено в `game/data/`:

| что | где | объём |
|---|---|---|
| палитра консоли (64 цвета) | `nes_palette.json` | — |
| графика Power Blade 2 | `pb2/tiles.png` + `pb2/chr.json` | 8192 тайла |

так же, как это делает консоль.  Это нужно, чтобы работали смена цвета костюма,
вспышка раненого врага и мигание палитр фона.

### Чем доказано

**Power Blade 2.**  Восемь кадров настоящей игры (этап 0), для каждого:
* карта тайлов, собранная из выгруженных данных, совпала с видеопамятью
  консоли — 640 из 640 тайлов и 40 из 40 байт палитровых признаков;
* картинка, нарисованная из `tiles.png` и палитр, совпала со скриншотом
  эмулятора — **0 расходящихся пикселей** вне спрайтов на всех восьми кадрах.

Проверка: `python3 work/extract/verify_pb2.py`.

**Solbrain.**  Десять кадров живой игры (этап 0, с проходом вправо), картинка
рисуется прямо из мировых координат через цепочку комната → экран → блок →
метатайл → тайл.  0 расходящихся пикселей на кадрах 3405, 3560, 3900, 4000,
4200, 4400; на остальных расхождения — спрайты (герой и враги), которые на
этом этапе ещё не рисуются.

Проверка: `python3 work/extract/verify_sol.py <дамп> <скриншот>`.

## Э1 — ядро движка

**Готово.**

Проект Godot 4.6 в `game/`.  Картинка собирается тем же способом, что на
консоли: карта номеров тайлов, лист тайлов глубиной в четыре цвета и палитра,
которая говорит, какие это цвета прямо сейчас.  Цвет нигде не запечён, поэтому
смена палитры видна на следующем кадре — на этом держатся вспышки, вода и
цвет костюма.

| файл | что делает |
|---|---|
| `src/nes_bg.gdshader` | отрисовка фона: тайл + палитра, как у консоли |
| `src/nes.gd` | палитра консоли, листы тайлов, палитра как текстура |
| `src/pb2_level.gd` | участок Power Blade 2, развёрнутый в карту тайлов |
| `src/sol_level.gd` | этап Solbrain (16x16 комнат) в карту тайлов |
| `src/clock.gd` | шаг логики 60.0988 Гц — кадр консоли, а не монитора |
| `src/pad.gd` | геймпад на двоих: клавиатура и джойстики, восемь кнопок |
| `src/main.gd` | сборка сцены, камера, пакетная съёмка для проверки |

## Э2 — герой Power Blade 2

**Готово.**

Герой ходит, бегает, прыгает, приседает, подкатывается, лазает по лестницам,
плавает, тонет в грязи, ездит на лентах и бьёт — теми же числами, что на
картридже. Положение хранится в 1/256 пикселя целыми числами, как в игре;
дробных чисел в логике нет.

| файл | что делает |
|---|---|
| `src/pb2_player.gd` | герой целиком: шаг, столкновения, позы, анимация |
| `game/data/pb2/player.json` | все константы, выгруженные из ПЗУ |
| `work/extract/pb2_player.py` | экстрактор этих констант |
| `work/tools/pb2_trace.py` | запись настоящей игры кадр за кадром |
| `work/extract/verify_player.py` | сверка движка с записью |

### Чем доказано

Покадровая сверка с картриджем. Для каждого сценария кнопок настоящая игра
проигрывается в эмуляторе, из памяти вынимаются **все** числа физики героя
(положение, обе скорости, состояние, обработчик, поза), потом те же кнопки
даются движку — и каждый шаг игры должен совпасть **до 1/256 пикселя**.

Последний прогон: `--all-areas --random=14 --seed=101`

```
0 of 350 scripts differ, 81565 frames matched
```

**350 сценариев на 25 участках, 81565 шагов подряд, ноль расхождений.**
Приёмка Э2 требовала 20 сценариев по 600 кадров — превышено в разы.

Проверка: `python3 work/extract/verify_player.py --all-areas --random=14 --seed=101`.

### Что разобрано по ходу и записано

`work/re/pb2_player.md` — поля героя, обработчики, ходьба, прыжок, тело,
чтение земли, подкат, лестница.
`work/re/pb2_collision.md` — типы поверхности и кэш.
`work/re/pb2_camera.md` — вид: кто решает, куда ехать, и кто едет.

Модель камеры проверена отдельно, на всех 63 участках по три сценария:
положение вида совпало везде.

### Долги Э2

1. **Участки, которые сверка пропускает** (38 из 63): в них слот 0 — не герой,
   или игра входит туда только по сценарию. Проверяются вместе с Э3.
2. **Не разобраны:** урон и отбрасывание, зацеп за уступ (костюм `$9A = 1`),
   бумеранг, тип участка 4 (`$AC1D`, встречается только в 1:0).
3. **Движок всё ещё получает с картриджа** положение вида, его сдвиг за кадр,
   коробки твёрдых предметов и хватку уровня. Это подпорки Э2, их снимает
   Э3.0.

## Э3.0 — вид считает движок сам / **Готово.**

Раньше движок получал положение вида готовым с картриджа. Теперь он его
считает: `game/src/pb2_camera.gd` — это `$D924` (разгон), `$D976` (езда) и
`$D3B8` (решение), плюс шесть участков, которые везут вид сами (`$2E`).

По дороге выяснились две вещи, из-за которых Э2 работал только с подпоркой:

* **шаг игры и кадр картинки — не одно и то же.** Один шаг двигает вид один
  раз. Шаг может перевалить через конец кадра, и тогда запись видит его
  дважды; считать сдвиги по кадрам нельзя;
* **в последнем кадре такой пары на герое иногда уже сказался разгон
  следующего шага.** При сверке этот чужой сдвиг возвращают назад.

Оба разобраны в `work/re/pb2_camera.md`.

Сверено: `--all-areas --random=12 --seed=59` — `0 of 300 scripts differ,
68132 frames matched`.

Файлы: `game/src/pb2_camera.gd`, `work/extract/pb2_area_auto.py`,
`work/re/pb2_camera.md`.

**Долги Э3.0:** коробки твёрдых предметов (`solids`), хватка уровня (`hold`) и
подвижный пол (`push`) по-прежнему приходят с картриджа — это Э3.2.
