# Проверка игровой сборки — 2 октября 2026

Продолжение: [геометрия, препятствия и два игрока](qa_geometry_2026-10-02.md).

Это первый проход по интеграционным ошибкам. Полное прохождение обеих
игр от начала до конца каждым героем **не подтверждено**. Старые зелёные
стенды проверяли отдельные механики и короткие прогоны; часть пилотов
восстанавливала здоровье или принудительно открывала двери.

## Исправления

| Проблема | Изменение | Проверка |
|---|---|---|
| В PB3 всегда загружалась пара Nova + Solbrain | Выбор 1/2 игроков и героя для каждого; доступны одинаковые герои | Переходы реального меню в `pb3_session_test.gd` |
| Верх/низ не двигали текстовый список | Все четыре стрелки работают, Enter/X запускают, Z возвращает к героям | Проверка меню |
| Nova на чужом уровне получал нулевое здоровье и неактивный слот спрайта | Живой игрок и его зеркало инициализируются при входе | Прогоны без восстановления здоровья |
| Игровой PB3 игнорировал дверь, интерлюдию и конец этапа | Сессия загружает назначение из состояния игры; очистка этапа возвращает список | PB2: дверь, босс, интерлюдия; Solbrain: дверь, смена этапа, очистка |
| Гибель оставляла попытку зависшей | Один погибший не завершает игру второго; гибель команды возвращает список | Смерть хозяина, гостя, команды и повторная попытка |
| Камера удерживала упавшего героя на последнем пикселе карты | Падение за карту фиксируется до ограничения камерой | Проверка нижней границы |
| Сценарий Solbrain не видел живого героя в команде из Nova | Сценарий следует за оставшимися игроками; урон идёт реальным персонажам | Вызов настоящего выхода `$A87C` |
| Solbrain не мог подняться по лестнице PB2 | На лестнице подключается родной контроллер PB2 с данными из ROM | Подъём, остановка, отпускание прыжком на экспортированной лестнице |
| Выбор снаряжения менял только меню | Выбранный костюм применяется к физике, оружие — к пулу; меню приостанавливает команду | Выбор в обеих играх и остановка движения |
| Из двух чужих героев рисовался только первый | Добавлен третий набор спрайтов с собственной палитрой и банками | Сравнение кадров с включённым и выключенным вторым гостем |
| Повторные входы удерживали старые миры в памяти | При выходе разрываются циклы ссылок персонажей, пулов и обратных вызовов | Завершение интеграционного прогона без ошибок освобождения ресурсов |
| Короткое нажатие могло потеряться между тиками | Событие сохраняется до ближайшего тика; клавиатура читается по физическим клавишам | Нажатие и отпускание между двумя тиками |

Решения для нового режима описаны в `work/re/pb3_session.md`. Кинематографические
переходы Solbrain в PB3 пока заменяются непосредственной загрузкой назначения.
При переходе команда восстанавливается; выбранное снаряжение сохраняется.

## Как играть

Запустить `game/project.godot`, выбрать **POWER BLADE 3**. В настройке выбрать
число игроков, P1 и P2; Enter открывает все 83 записи: 63 области Power Blade 2
и 20 этапов Solbrain. X/Enter запускает выделенную запись.

| Действие | Игрок 1 | Игрок 2 |
|---|---|---|
| Движение | Стрелки | WASD |
| Прыжок | X | `'` |
| Атака | Z | `;` |
| Снаряжение | Enter | Q |
| Вернуться к уровням | Shift | — |

Клавиши указаны по английским позициям. Сохранено управление двумя геймпадами;
физические геймпады в этом проходе не проверялись. Меню снаряжения общее по
паузе: пока оно открыто у одного игрока, мир стоит для обоих.

## Воспроизведение проверок

Пройдены **13 целевых стендов**: `solrun`, `pb3floor`, `pb3pair`,
`pb3pick`, `pb3hits`, `pb3gear`, `pb3list`, `pb3run`, `pb3session`,
`build`, `ask`, `keep`, `pb3draw`. После изменений отрисовки повторно
прошли `pb3session`, `pb3draw` и экспорт `build`: 0 ошибок из 3 стендов.
Сводка последних результатов сохранена в `docs/qa/checks.txt`.

Новый прогон: **498 запусков, 58 563 тика без бессмертия**; проверки
игрового цикла прошли. Старые проверки включили 5185 проходов по чужой
геометрии, 2460 сценариев общей камеры, 49 488 размещений для проверки
урона, 332 коротких прогона пар и 7 сравнений экспорта macOS с исходниками.

Стенд `pb3draw` проверяет композицию фиксированного участка и совпадение
пикселей со старой одиночной отрисовкой; он не проверяет завершение этапа.
Выбор героев, реальный игровой цикл и третий набор спрайтов проверяет
`pb3session`, включая отдельный запуск с настоящим рендерингом.

```sh
python3 work/extract/verify_pb3_session.py
python3 work/extract/verify_pb3_session.py --quick
python3 work/extract/verify_all.py --only=solrun,pb3floor,pb3pair,pb3pick,pb3hits,pb3gear,pb3list,pb3run,pb3session,build,ask,keep,pb3draw
/Applications/Godot_mono.app/Contents/MacOS/Godot --path game --script res://tests/pb3_session_test.gd -- --quick --capture
```

Новый стенд открывает каждый участок в шести составах: два одиночных и
четыре парных. Он шагает до 120 тиков обычными командами, без бессмертия.
Проверки дверей отдельно задают исходное состояние перехода; это проверка
загрузчика, **не доказательство**, что до каждой двери можно дойти.

Кадры рендеринга сохраняются в `docs/qa/`. Проверка второго чужого героя
сравнивает область его тела с кадром, где его слой выключен: оружие или
посторонние пиксели за пределами тела не могут дать ложный успех.

## Основа для онлайна

`Pb3Session.advance(tick, buttons)` получает упорядоченные команды игроков.
Она отделена от клавиатуры, окон и часов; повторный или пропущенный тик
отвергается. Сравниваются результаты повторного проигрывания одних команд.
В будущем здесь можно подключить сервер, который принимает команды и
рассылает состояние. Сетевой транспорт, сохранение полного состояния,
переподключение и межплатформенная синхронизация пока не реализованы.

## Что остаётся неподтверждённым

* Полные маршруты, все бои с боссами и секретные области без принудительных
  переходов, каждым героем и каждой парой.
* Все особые взаимодействия чужого героя с движущимися платформами, водой,
  ловушками и сценариями поздних этапов.
* Полная приёмка всех старых стендов, включая многочасовую сверку физики с
  картриджами; текущий прогон целевой.
* Проверка управления реальными двумя геймпадами и сборок Windows/Linux.

Наличие записи в списке уровней означает возможность её запустить;
оно не означает, что полный маршрут этой записи уже пройден тестировщиком.
