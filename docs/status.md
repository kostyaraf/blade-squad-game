## Э1: два игрока

Сборка: `python3 work/pb3/v2/build.py` → `work/build/PB3.nes` (384 КБ PRG,
mapper 4, 8 КБ работающей памяти картриджа).

Как это устроено, в двух словах: весь контекст игрока в Solbrain — это
непрерывный кусок памяти в 50 байт. Новый код (732 байта, живёт в памяти
картриджа по адресу `$6000`, которую оригинал не трогает) на каждом кадре
вызывает штатное обновление игрока дважды, между вызовами меняя местами этот
кусок с копией второго игрока и заодно подменяя зеркала джойстиков. Движок при
этом каждый раз считает, что игрок один — поэтому все его механики работают
без переписывания.

Второй игрок входит в игру кнопкой START на втором джойстике. Один раз вошёл —
дальше возвращается сам после каждого перезапуска уровня.

### Проверено прогоном

`python3 work/pb3/v2/acceptance.py` — 11 проверок, все проходят:

* без второго джойстика игра остаётся обычной одиночной (`P2_ON=0`);
* START на втором джойстике вводит второго бойца;
* два джойстика разводят бойцов в разные стороны (разрыв 224 пикселя);
* оба остаются на одном экране — камера идёт за парой, край её не роняет;
* оба бьют одновременно (у второго — свой слот удара `$0D`, который движок и
  так проверяет по врагам);
* здоровье у каждого своё и действительно убывает;
* один выбывает — второй продолжает играть, выбывший через 120 кадров встаёт
  рядом с напарником и слушается своего джойстика;
* оба выбывают — отрабатывает штатная смерть движка, уровень перезапускается,
  пара возвращается в игру.

Снимки: `docs/e1/apart__2350.png` (двое у разных краёв экрана),
`docs/e1/punch__2113.png` (оба в ударе), `docs/e1/join__2350.png`.

## Долги Э1 — что честно не сделано

1. **Враг занят только ближним игроком.** Каждый враг на кадре достаётся тому,
   кто ближе; для дальнего он в этот момент неподвижен. Заметно, когда бойцы
   разошлись по краям экрана.
2. **Общие на двоих:** спутник (слот `$0C`), слот оружия `$0E`, пул выстрелов
   (8 штук) и HUD. HUD показывает того игрока, чей контекст сейчас в живой
   памяти, то есть фактически первого.
3. **Лимит спрайтов** (58, `15:$F4D0 CMP #$3A`) измерялся только в первой
   комнате. В густых сценах двое бойцов могут его продавить — не проверено.
4. **Выбора персонажа нет.** Второй боец — пока копия первого. Это Э2.
5. Возрождение ставит бойца ровно на ноги напарнику (шаг в сторону иногда
   попадает в стену, и боец там залипает). На кадр они накладываются.
6. Проверки шли по первой комнате первого уровня. Полный прогон уровня в двоём
   — после Э4/Э5, когда уровни будут свои.
