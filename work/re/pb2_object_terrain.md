# Power Blade 2 — что вещь видит под собой

Герой спрашивает местность своим путём, и он уже перенесён
(`class_byte` в `pb2_level.gd`). Вещи спрашивают её через `$F342`
(переходник `$C888`), и ответ в итоге приходит из того же места — но
дорога туда своя, и в ней есть то, чего у героя нет.

## Вход

`JSR $C888` с `A` — сдвиг вбок от вещи, `Y` — сдвиг вниз, оба со знаком.

`$F342` складывает место вещи со сдвигом в четыре байта нуля страницы:

```
$12:$13 := $04F2,X:$0508,X + A   (вбок: экран, точка)
$10:$11 := $04B0,X:$04C6,X + Y   (вниз: экран, точка)
```

### Прежде всего — точку загоняют в область

`$F36A`. Уровень широк только в одну сторону; поперёк он ровно в один экран,
и вопрос поперёк никогда не выпускают за его край — его подтягивают к краю:

* **область вниз** (`$97` не ноль): по `$12` (экран вбок) — ноль ничего не
  меняет, больше нуля даёт `$13 := $FF`, меньше нуля `$13 := $00`;
* **область вбок** (`$97` ноль): по `$10` (экран вниз) — больше нуля даёт
  `$11 := $AF`, меньше нуля `$11 := $10`, а при нуле `$11` просто зажимают
  в `$10`..`$AF`.

Старший байт при этом **не трогают**, и дорога дальше всё равно смотрит на
него: подтянута точка или нет, `$F3FC` по ненулевому `$10` или `$12` уходит на
прямое чтение карты.

Дальше — по виду области `$87` через таблицу слов `$F3AA`/`$F3BA`
(16 входов):

| вид | ведёт на |
|---|---|
| 4 | `$F40D` |
| 7 | `$F3CA` |
| 10 | `$F3E3` |
| 15 | `$F42C` |
| остальные | `$F3FC` |

## Обычная область — `$F3FC`

```
если $10 или $12 не ноль        -> $F42C   ; точка не на этом экране
если $11 >= $B0                 -> $F42C   ; ниже видимого
иначе                            -> $F52C с A = $13, Y = $11
```

`$F52C` — тот самый запрос по клетке, что и у героя: ряд ищут сложением
`$FC` (или `$E0` для горизонтальных областей) с точкой вниз, с перескоком
через шестнадцать строк, что отделяют экран в 240 от страницы в 256, и
берут два бита на клетку 16×16 из её левого верхнего угла. Ответ — один
из четырёх байтов таблицы `$F5A9`.

Иначе говоря: `$F52C` = `class_byte(px, py)` движка.

## Вид 7 — `$F3CA`

```
если точка не на экране  -> $F42C, и если ответ ровно 3 -> вернуть $80
если $11 < $90           -> как $F3FC
иначе                     -> вернуть $80  ; всё ниже $90 — сплошная стена
```

## Вид 10 — `$F3E3`

```
если точка не на экране  -> $F42C
если $11 >= $98          -> как $F3FC
если $11 <  $29          -> как $F3FC
иначе                     -> спросить не ту точку, а ряд $9C
```

`$29` — верхняя граница подвижной части области; между ней и `$98` вся
полоса отвечает так же, как ряд `$9C`.

## Вид 4 — `$F40D`

```
если точка не на экране  -> $F42C
если $11 >= $80          -> как $F3FC
если $11 >= $29          -> вернуть 0   ; пусто, сквозь
иначе                     -> спросить ряд ($11 - $29 + $80)
```

Это область с перевёрнутым куском: всё выше `$29` спрашивают со сдвигом
вниз на `$80 - $29`, а полоса между `$29` и `$80` пуста.

## Не на экране — `$F42C`

`$F42C` переключает банк на банк уровня (`$DFC9`) и читает карту напрямую
через `($35)` — список экранов — и `($37)` — список клеток, добавив к
точке начало области `$66`:`$67`.

* **область вбок**: `$11 := $11 − $10` (те шестнадцать строк, которых экран
  не показывает), `$13 := $67 + $13`, экран `:= $66 + $12`;
* **область вниз**: строку складывают с `$66`:`$67` и переводят из страниц по
  240 строк в страницы по 256, прибавляя по шестнадцать за страницу
  (`$F45B`..`$F495`); знак берут у **исходного** `$10` (`BIT $10` до записи).

Дальше клетку ищут по `($35)` — экран — и `($37)` — его карта, и номер плитки
переводят в вид местности списком порогов `($7B)`/`($7D)`. **Ответ у него свой,
не тот, что у `$F52C`:** `$F52C` возвращает один из четырёх байтов `$F5A9`, а
`$F42C` — то, что лежит в `($7D)`, то есть вид местности как он есть. Отсюда и
`CMP #$03` у вида 7: это сравнение с видом, а не с классом.

Движку отдельная дорога не нужна: у него вся область лежит целиком, и
`class_byte` по мировой точке отвечает и за экраном тоже. Но домен ответа
разный, и это надо повторить: за экраном отвечать `terrain_at`, на экране —
`class_byte`.

## Через кадр

Обработчики почти никогда не зовут `$C888` напрямую — они зовут `$FB88`
(`$C945`) или `$FB92` (`$C948`), а те спрашивают местность только в свою
очередь: `(X EOR $0119) AND 1` (см. [pb2_object_move.md]). Не в свою
очередь `$FB88` отвечает «пусто», `$FB92` — «упёрлось».

Это надо переносить как есть: вещь видит землю через кадр, и на этом
держатся её походка и то, как она сваливается с края.

## Ответ

Четыре байта таблицы `$F5A9` — `00 01 80 02`:

| значение | что |
|---|---|
| `$00` | пусто |
| `$01` | лестница |
| `$80` | стена |
| `$02` | вода |

Они уже лежат в движке (`class_bytes` в `pb2_level.gd`), и герой ими
пользуется — вещи должны читать те же.
