# Power Blade 2 — что банк 10/11 умеет просить у постоянного банка

Код вещей живёт в паре банков 10/11 (`$8000`-`$BFFF`), а всё общее — движение,
столкновение с уровнем, рисование, звук — в постоянных банках 14/15
(`$C000`-`$FFFF`).  Между ними стоит **таблица переходников**: подряд идущие
`JMP` в банке 14, с `$C810` по `$C97D`.  Обработчик типа никогда не зовёт
`$Fxxx` напрямую — он зовёт переходник, и это единственная его связь с
остальной игрой.

Отсюда следует важное: **список этой таблицы — полный список того, что вообще
умеют вещи**.  Перенести его — значит перенести всё, что нужно любому из
девяноста типов, и после этого каждый обработчик становится коротким.

Составлено из ПЗУ (`work/tools/lin.py "Power Blade 2 (USA).nes" 14 C810 C97E`).
Ниже — таблица целиком; столбец «что это» заполняется по мере разбора.

## Соглашение о вызове

Почти всё берёт вещь из `X` (номер места в таблице объектов) и работает с
полями `$0400,X`, `$0416,X` и так далее.

Два переходника читают **данные, положенные сразу за `JSR`** — обычный для
этой игры приём, из-за которого линейный разбор кода сходит с рельсов:

* `$C84F` -> `$CA0B` — переход по таблице слов, положенной за `JSR`.
  В `A` — номер строки таблицы;
* `$C97E` -> `$FD10` — то же самое, но номер берётся сам, из `$058C,X`
  (состояние вещи).  Обычное начало обработчика: `JSR $C97E`, а за ним столько
  слов, сколько у вещи состояний.

Разбирая обработчик, после такого `JSR` надо пропустить `2 * (число состояний)`
байт и продолжать с адресов из таблицы.

## Поля вещи

Таблица объектов — 22 места, поле *f* вещи *n* лежит по `$0400 + 22*f + n`.
Место 0 — герой, места 6..$15 — всё остальное. Что из этого чем оказалось:

| адрес | что |
|---|---|
| `$0400,X` | тип; ноль — место пустое |
| `$0416,X` | пометка; `$08` ставится при рождении, ещё пять значений ставят `$C99F`..`$C9AB` |
| `$042C,X` | биты состояния; бит 6 — куда смотрит |
| `$0442,X` | поза (номер картинки) |
| `$0458,X` | какой ряд картинок проигрывается |
| `$046E,X` | шаг внутри ряда |
| `$0484,X` | номер записи списка уровня, с единицы; ноль — не из списка |
| `$049A,X` | байт три записи (у собираемого — какой он по счёту) |
| `$04B0,X`:`$04C6,X` | место вниз по экрану, старший и младший |
| `$04F2,X`:`$0508,X` | место вбок по экрану, старший и младший |
| `$0534,X`:`$054A,X` | скорость вниз, старший и младший |
| `$0560,X`:`$0576,X` | скорость вбок, старший и младший |
| `$058C,X` | состояние (номер строки в таблице за `JSR $C97E`) |
| `$05A2,X` | сколько ещё держать картинку |
| `$05B8,X` | оглушение: пока не ноль, ход пропускают (`$8026`) |
| `$05CE,X` | на откуп типу (у `$2C` — «уже приземлился») |
| `$05E4,X` | на откуп типу |
| `$05FA,X` | на откуп типу; при смерти — ответ `$B729` (0 или 1), у двери — куда она ведёт |
| `$0610,X` | на откуп типу; при смерти обнуляют, у двери — вторая половина того, куда она ведёт |
| `$0626,X` | сторона отброса (`$B38E`); у двери — счётчик ухода |

Полей всего 29 (`$0400`..`$0668`), по 22 байта на поле.

Скорость складывается с местом не здесь — этим занят общий шаг движения; сами
обработчики только задают её (`$C906`/`$C909`) и подправляют (`$C90C`/`$C912`).


## Что осталось неразобранным

Из 122 переходников банки 10/11 зовут 81; выше расписано около сорока.
Остальное — рисовка (`$C8xx` в области `$D4xx`/`$EExx`), звук и работа с
уровнем (`$DFC9`, `$F497` — запрос местности под точкой). Их надо разобрать
до того, как браться за отдельные типы: пока их нет, любой обработчик
упирается в них с первой же строки.

Порядок, который из этого следует:

1. движение и тяжесть (`$C8EE`..`$C8F7`, `$C906`..`$C921`) — общее для всех;
2. запрос местности под точкой (`$C885`, `$C888`) — кто на чём стоит;
3. рисовка (`$C837` и ряд картинок) — без неё вещь не видно;
4. столкновение с героем и урон;
5. и только потом девяносто типов по одному.


## Ряды картинок

Ряд — короткая запись в банке вещей; таблица слов на все ряды лежит по
адресу из `$802D`:`$802E` того банка (карта банков `$36`).

| байт | что |
|---|---|
| 0 | последний шаг ряда; бит 7 — шаги идут не подряд, а по списку |
| 1 | сколько кадров держать картинку (`$05A2,X`) |
| 2 | с какой позы ряд начинается |
| 3 | (только при бите 7) какой список шагов, номер в таблице `$E39C` |

Четыре списка шагов:

| номер | адрес | шаги |
|---|---|---|
| 0 | `$E3A4` | 0 1 0 2 |
| 1 | `$E3A8` | 0 1 2 1 |
| 2 | `$E3AC` | 0 1 2 3 3 2 1 |
| 3 | `$E3B3` | 0 2 |

`$E2D5` (`$C83A`) — начать ряд `A`:

```
$0458,X := A          ; какой ряд играет
$05A2,X := ряд[1]     ; сколько держать
$0442,X := ряд[2]     ; поза
$046E,X := 0          ; шаг внутри ряда
```

`$E30F` (`$C837`) — шаг ряда, зовут раз в кадр:

```
$05A2,X := $05A2,X - 1
если не ноль -> выйти
$05A2,X := ряд[1]
$046E,X := ($046E,X = ряд[0] & $7F) ? 0 : $046E,X + 1
$0442,X := ряд[2] + ($046E,X  или  список[$046E,X])
вернуть $0442,X в A
```

`$E309` — то же, но ряд берут из `A`, а не из `$0458,X`: тик, и по
истечении перейти на другой ряд.

### Куда смотрит вещь

Бит 6 в `$042C,X`. Ставят и читают так:

| зовут | что делает |
|---|---|
| `$FD54` (`$C990`) | перенос взведён, если бит 6 стоит |
| `$FD5F` (`$C993`) | поставить бит по знаку скорости вбок: вправо — стоит |
| `$FD41` (`$C98D`) | `$CADB`, и сравнить его перенос с битом 6 |

### Пометка `$0416,X`

При рождении `$E4F5` кладёт `$08`. Пять переходников кладут другое:

| зовут | значение |
|---|---|
| `$C99F` (`$FD76`) | `$01` |
| `$C9A2` (`$FD7A`) | `$02` |
| `$C9A5` (`$FD7E`) | `$20` |
| `$C9A8` (`$FD82`) | `$40` |
| `$C9AB` (`$FD86`) | `$80` |

Шесть значений, все — отдельные биты: это разряд, а не число. Похоже на то,
чем вещь отвечает при столкновении (кого можно бить, кто бьёт сам).

### Покачивание — `$FD1D` (`$C981`)

```
A := $04C6,X                 ; $FD16: A := A + $04C6,X
если область вертикальная: A := A + $67
Y := $FD31[A & $0F]
подвинуть вниз на Y
```

`$FD31` = `FF FE FD FC FB FA F9 F8 07 06 05 04 03 02 01 00` — половина
волны вниз, половина вверх, шаг по младшим четырём битам места. Оттого все
покачивающиеся вещи в области качаются в лад друг с другом: фаза берётся не
из времени, а из того, где вещь стоит.

### Не на экране — `$FD8C`

Перенос взведён, если `$04F2,X` или `$04B0,X` не ноль.


## Второе соглашение: довод лежит в коде

Кроме таблицы состояний за `JSR` есть ещё одно место, где за вызовом лежат не
команды, а числа. В банке 11 стоят три сборщика доводов:

| зовут | сколько байт за `JSR` | что отдаёт |
|---|---|---|
| `$BE45` | 1 | `A` |
| `$BE4E` | 2 | `A` — второй байт, `Y` — первый |
| `$BEEF` | 3 | `$00` — первый, `Y` — второй, `A` — третий |

Все трое зовут `$C8C7` (`$F1C9`), который переписывает нужное число байт из-за
адреса возврата в `$0180`.. и сдвигает сам адрес возврата — поэтому возврат
приходит **за** довод.

Вокруг них — короткие обёртки: «взять довод и положить в поле», «взять два и
задать скорость». Каждая такая обёртка съедает столько байт кода, сколько
берёт её сборщик.

| `$BEAD` | `$C83A` (`$E2D5`) |

По два (`$BE4E`): `$BEB3`->`$C906`, `$BEB9`->`$C909`, `$BEBF`->`$C900`,
`$BEC5`->`$C903`, `$BECB`->`$C945`, `$BED1`->`$C948`, `$BED7`->`$C94B`,
`$BEDD`->`$C94E`, `$BEE3`->`$C951`, `$BEE9`->`$C960`.

По три (`$BEEF`): `$BF00`->`$C954`, `$BF06`->`$C957`, `$BF0C`->`$C95A`,
`$BF12`->`$C95D`.

`$BE6A` довода не берёт: он просто кладёт `$FF` в `$049A,X` — «убить нельзя».

Без этих двух соглашений линейный разбор обработчика рассыпается на третьей
команде. Разбирать их надо, идя по коду: `work/tools/objdis.py <тип>`.


## Родить вещь — `$F8A1` и родня

Всё, что вещь выпускает из себя — выстрел, осколок, второго врага, — родится
одинаково. Мест для этого своих: **`$06`..`$0D`**, те, которые список уровня
не берёт никогда (`$CB1B` ищет свободное только среди них и взводит перенос,
если свободного нет).

`$F8A1` (`$C8DF`) — родить вещь типа `$24` (переменная `$24`, не тип номер
`$24`) со сдвигом от себя:

```
A -- сдвиг вбок, со знаком;  Y -- сдвиг вниз, со знаком
$F924: $10 := $0508,X + A  (с переносом в $04F2,X)
       $11 := $04C6,X + Y  (с переносом в $04B0,X)
       если хоть один старший байт вышел не в ноль -- снять адрес возврата
       со стека и вернуться с взведённым переносом: ребёнка не будет
$CB1B: найти свободное место среди $06..$0D; нет -- перенос взведён
       $0400 := $24;  $0416 := $08;  $0508 := $10;  $04C6 := $11
       $12 := место ребёнка;  перенос сброшен
```

То есть ребёнок не родится, если точка рождения ушла за край экрана.

Рядом:

| зовут | что |
|---|---|
| `$F8C9` | посчитать точку так же и уйти в `$F88F` |
| `$F8D3` | то же, но в `$F89E` |
| `$F8DD` | родить **на своём же месте**, ещё и позвать `$F5BA` (`$26`, `$06`) |
| `$F913` | `$24 := A`, `$26 := Y`; вернуться, если сам не на экране |


## Ход всех вещей — `$8000` банков 10/11

Зовут его раз в кадр из `$CF1C`. Это единственное место, где вещь получает
ход.

```
$8003: если $27 >= 5 -> выйти          ; ход только в обычной игре
       JSR $BF18                       ; сперва герой
       $011F := 0                      ; счётчик твёрдых коробов
       $0166 := 0;  $0167 := 0
       $0119 := $0119 + 1              ; счётчик кадров, по которому $FB81
                                       ; делит запросы местности пополам
$801A: X := 6
$801C: если $0400,X = 0 -> следующий
       JSR $8134 (отсев)
       перенос взведён -> $8075: JSR $C810 ($D6D4, очистить место), следующий
$8026: если $05B8,X (оглушение) не ноль -> $8043
$802B: если $2A = 0 -> ход
       иначе ход только у типов $03 и $04     ; $2A замораживает уровень
$803A: JSR $807A                       ; ум по типу
$803D: X := X + 1;  пока X != $16
```

Порядок внутри кадра для одного места: **отсев, потом оглушение, потом ум**.
Отсев идёт до всего, и место, которое он забрал, ум в этом кадре не получит.

### Оглушение — `$8043`

```
$05B8,X := $05B8,X - 1
если тип >= $4F         -> ход всё равно ($802B)
если тип  = $38         -> ход
если тип  > $38         -> $806B
если тип  = $10 или $13 -> ход
если тип  < $1D         -> $806B
если тип  < $20         -> ход
если тип  < $2C         -> $806B
если тип  < $2F         -> ход
$806B: если $049A,X >= $20 -> ход
       иначе хода нет
```

То есть оглушённая вещь всегда считает счётчик вниз, а ход пропускает только
мелочь: боссы (`$4F`+), `$10`, `$13`, `$1D`..`$1F`, `$2C`..`$2E`, `$38` и всё,
у кого здоровья `$20` и больше, продолжают ходить и оглушёнными.

### Как устроен `$CA0B`

```
Y := 2*A + 1
$00:$01 := снятый со стека адрес возврата   ; это последний байт JSR
$02:$03 := ($00),Y и ($00),Y+1
JMP ($0002)
```

Возврата на место вызова не будет: `$CA0B` **прыгает**, а адрес возврата уже
снят. Обработчик вернётся туда, откуда звали звавшего. Линейный
разбиратель после такого `JSR` сходит с рельсов — за ним лежат слова, а не
код.

## Тип `$04` — дверь в конце области

Самый частый тип в игре (52 записи из 525) и тот, без которого нельзя Э3.1:
это он уводит из области в область.

Состояния (таблица слов за `JSR $C97E` по адресу `$8545`):

```

4 -> $86D2   5 -> $86E7   6 -> $9ABD

Состояние 0 — стать собой:

```
если $049A,X не ноль:
        если $BE36[$53] AND $5B -> $D6D4      ; на этом участке двери нет

$00:$01 := $8587[$53]                          ; таблица участка

## Далеко ли герой — `$FB25` и `$FB4B`

`$FB25` (`$C93C`) вбок, `$FB4B` (`$C93F`) вниз. Обе отвечают тремя вещами
сразу, и одна из них — флаг переполнения:

* **`V` взведён** — герой не на этом экране, ответа нет; `A` бессмысленно,
  перенос только говорит, в какую сторону он ушёл. Все умы начинают с `BVS`.
* **`V` сброшен** — `A` есть расстояние по модулю, перенос взведён, если герой
  **не дальше** вещи по оси (вещь стоит за ним), сброшен — если дальше.

Сделано это через `BIT` по паре байтов данных `$FB71` = `00 40`: бит 6 нуля
даёт `V` сброшенным, бит 6 сорокового — взведённым. Читать `$FB71`/`$FB72`
как код нельзя, это данные.

Отрицание модуля, когда вещь ближе к началу, делает `$CAEB`.

## Ход картинки — `$E2D5` и `$E30F`

Оба в банке 15; переходники `$C83A` и `$C837`. Списки лежат в банке 10 по
указателю в `$802D`:`$802E` — таблица слов, номер хода в неё индексом.

Запись хода — три байта:

| байт | что |
|---|---|
| 0 | последний шаг; старший бит — запись длиннее (`$E362`) |
| 1 | сколько кадров держать шаг |
| 2 | картинка первого шага |
| 3 | только когда у байта 0 стоит старший бит: какой список сдвигов брать |

Обычная запись — три байта, и картинка идёт подряд: база плюс шаг. Запись со
старшим битом — четыре, последний шаг это байт 0 без старшего бита, а картинка
= база плюс число из списка по номеру шага. Списки — слова в банке 15 по
`$E39C`: `$E3A4`, `$E3A8`, `$E3AC`, …

Таблица ходов лежит **не в банке 10**, а в паре 6/7: `$E2D5` сперва зовёт
`$ECA7` с `Y = $36`, а это ставит банк 6 на `$8000` и банк 7 на `$A000`, и уже
там читает `$802D`:`$802E`. Указатель — `$B0F6`, первая запись `$B174`, то есть
**63 хода**.

Поля вещи, которые этим заняты:

| поле | адрес | что |
|---|---|---|
| f4 | `$0458,X` | номер хода |
| f5 | `$046E,X` | какой шаг хода идёт сейчас |
| f19 | `$05A2,X` | сколько кадров осталось держать шаг |
| f3 | `$0442,X` | картинка = байт 2 записи плюс шаг |

`$E2D5` (`$C83A`, обёртка `$BEAD` с однобайтовым доводом) — **начать ход**:
номер в f4, шаг в ноль, держать столько, сколько сказано, картинка первая.

`$E30F` (`$C837`) — **продвинуть ход**: f19 убавляется, и пока не ноль ничего
не происходит; на нуле f19 берут заново, шаг растёт (дойдя до последнего,
сбрасывается в ноль), и картинка = база плюс шаг.

`$E309` (`$C88E`) — то же самое, но номер хода берётся **не из f4, а из `A`**:
`$E309` убавляет f19 и на нуле входит в ту же дорогу на байт позже, минуя
`LDA $0458,X`. То есть «доведи шаг до конца и продолжай уже другим ходом».

Отсюда следует: списки ходов надо вынуть экстрактором из банка 10, как вынуты
картинки подбираемого (`$8401`).
