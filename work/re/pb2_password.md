# Экран пароля Power Blade 2 — `$9672`

Экран, на который уходит вторая строка заглавного экрана (`$18` = 2,
`$8018` = `$9672`, банк-пара 0). Двенадцать цифр по восьмеричной цифре
каждая, каретка между ними, и на START — приговор: либо игра начинается с
тем, что пароль объявил, либо экран говорит «нет».

Всё снятое здесь — дизассемблером пары 0 и трассой эмулятора.

## Шаги — `$19`

`$9672` берёт `$19` и прыгает по таблице слов `$9677` (`JSR $C84F` =
`$CA0B`). Четырнадцать входов:

| `$19` | адрес | что это |
|---|---|---|
| 0 | `$9693` | поднять экран набора |
| 1 | `$96CE` | набор идёт: кнопки и START |
| 2 | `$972A` | `DEC $50`, пока не ноль; потом дальше |
| 3 | `$9732` | уйти: `$18` := 3 (или 4, если `$5B` = `$1F`) |
| 4 | `$9760` | поднять экран **показа** пароля |
| 5 | `$97A7` | дождаться `$C8` = 0 и поставить каретку |
| 6 | `$97B7` → `$983F` | показ: SELECT водит каретку, START берёт |
| 7 | `$97BA` | по `$4F` — либо снова набор, либо в игру |
| 8 | `$97E1` | поднять поле цифр для показа |
| 9 | `$97FC` | выписать двенадцать цифр, по одной на картинку |
| 10 | `$9810` | стоять, пока не нажмут START |
| 11 | `$981A` | нули в `$18`, `$19`, `$5B`, `$56`, `$2B`, `$2C`, `$57` |
| 12 | `$972A` | то же ожидание, что и шаг 2 |
| 13 | `$9835` | дождаться `$80D9` и `$19` := 0 |

Шаги 0–3 и 12–13 — **набор**: игрок вводит пароль. Шаги 4–11 — **показ**:
игра называет пароль, которым можно вернуться. Входят в экран обоими
концами: с заглавного экрана — с `$19` = 0, из игры — с `$19` = 4.

Э7.6 переносит набор, Э7.7 — показ и то место игры, которое на него
посылает (`$D050`: жизни кончились).

## Поле: двенадцать цифр

`$0690..$069B` — то, что стоит на экране: по цифре 0..7 на место.
`$0680..$068B` — то же поле, но уже разложенное (см. ниже).

`$51` — где каретка. Мест двенадцать, четыре в ряд и три ряда; где они
стоят на экране, говорят две таблицы:

```
$9928:  50 70 90 B0 50 70 90 B0 50 70 90 B0     ; вбок
$9934:  68 68 68 68 88 88 88 88 A8 A8 A8 A8     ; вниз
```

Каретка — место 0 без типа, как и на заглавном экране: `$9914` пишет
`$0442` := `$59`, `$0508` из `$9928`, `$04C6` из `$9934`, а `$0400` не
ставит никто.

## Кнопки — `$987A`

Читается `$48` — **нажатое только что** на первом паде, — и разбирается
сдвигами, бит за битом:

| кнопка | бит | что делает |
|---|---|---|
| RIGHT | 0 | `$51` + 1, с `$0B` на 0 (`$9891`) |
| LEFT | 1 | `$51` - 1, с 0 на `$0B` (`$98A3`) |
| DOWN | 2 | `$51` + 4, за край — ещё + 4 и `AND #$0F` (`$98B3`) |
| UP | 3 | `$51` - 4, за край — `AND #$0F` и ещё - 4 (`$98CD`) |
| B | 6 | цифра на месте - 1, `AND #$07`, **просьба `$1D`** (`$98E5`) |
| A | 7 | цифра на месте + 1, `AND #$07`, **просьба `$1D`** (`$98FA`) |

Каждый ход каретки — **просьба `$39`** (`$990F`), и за ней сразу `$9914`,
которая каретку и переставляет. Цифра, которую поменяли, перерисовывается
через `$9940`.

START (бит 4) на шаге 1 читается раньше всех, в `$96CE`, и до `$987A` дело
тогда не доходит; SELECT (бит 5) на наборе не читается вовсе.

## Приговор — `$9A03`

```
$9A03  JSR $9B09      ; снять сдвиг
       JSR $9BC4      ; достать код и разложить
       JSR $9C2B      ; сумма
       BCS плохо
       JSR $9CCF      ; что обязано быть нулём
       BCS плохо
       JSR $9D6C      ; и ещё раз то же, но полями
       BCS плохо
       CLC / RTS      ; годится
```

**Сдвиг** (`$9B09`). У каждого места своя постоянная, и она вычитается из
цифры по модулю восемь:

```
$9AFD:  04 01 03 02 07 01 03 05 06 04 05 02
$0690[i] := ($0690[i] - $9AFD[i]) AND 7
```

Обратное (`$9AE9`, сторона показа) — прибавить то же самое.

**Код** (`$9BC4`). Пять бит собираются из трёх мест поля:

```
$06A0 := (($0698 AND 6) >> 1) OR (($0696 AND 6) << 1)
                              OR (($069B AND 4) << 2)
```

**Раскладка** (там же). Код выбирает одну из четырёх перестановок:

```
$9B74: указатели, шестнадцать слов, по кругу
       $9B94 $9BA0 $9BAC $9BB8 $9B94 ... ; то есть код AND 3
$9B94:  00 02 03 01 04 06 09 05 07 08 0A 0B
$9BA0:  08 02 03 06 0A 01 09 05 07 00 04 0B
$9BAC:  05 04 03 0A 06 00 09 08 07 01 02 0B
$9BB8:  03 04 01 02 06 05 09 0A 07 08 00 0B
$9B68:  00 06 05 04 0A 01 09 03 07 08 02 0B  ; особая, для кода $1F
```

`$0680[perm[i]] := $0690[i]` для i = 0..11. Индекс берут как
`(код AND $0F) * 2`, а особую — когда код в точности `$1F`.

**Сумма** (`$9C2B`). Складывают не всё поле, а те его биты, которые сумму
не несут:

```
s := $0680[0..5] целиком
   + ($0680[6..10] AND 6)
   + ($0680[11] AND 4)                      ; всё по модулю 256
$06A5 := s
```

и требуют, чтобы её биты стояли в младших битах старших мест:

```
s бит 0   == $0686 AND 1
s бит 1   == $0687 AND 1
s бит 2   == $0688 AND 1
s бит 3   == $0689 AND 1
s бит 4   == $068A AND 1
(s AND $60) >> 5 == $068B AND 3
```

**Что обязано быть нулём** (`$9CCF`). Если код `$1F` — семь проверок по
полю (`$0680 AND 2`, `$0681 AND 6`, `$0682 AND 6`, `$0683 AND 2`,
`$0684 AND 2`, `$0685 AND 6`, `$0686 AND 4` — все нули); иначе одна:
`$06A0 AND $10` = 0. То есть пятый бит кода в одиночку не ходит: либо все
пять этапов, либо ни одного пятого.

**И ещё раз то же, полями** (`$9D6C`). `$9DAA` (или `$9E52` для кода
`$1F`) собирает из поля четыре байта `$06A1..$06A4` и требует, чтобы все
четыре были нулём. Это те биты, которые у пароля свободны: очки. Пароль,
у которого они не нули, — не пароль этой игры.

## Что пароль объявляет — `$9D12`

```
$5B := $06A0                              ; пройденные этапы, бит на этап
$2C := $06A1, $2B := $06A3                ; очки -- нули, см. $9D6C
$9E := $06A2, $9D := $06A4
$56 := (($0688 AND 6) >> 1) OR (($068A AND 6) << 1)   ; найденные костюмы
```

Обе половины `$9D12` (для `$1F` и для остального) делают одно и то же:
код в картридже удвоен.

Итого пароль несёт **девять бит**: пять `$5B` и четыре `$56`. Остальное —
сумма, перестановка и сдвиг.

Годных кодов не тридцать два, а семнадцать: `$00`..`$0F` и `$1F`.

## Куда экран уходит

На годном пароле (`$96FD`): `$9D12`, потом `$53` := 0 (а если `$5B` =
`$1F`, то 5), `$9C` := 0, **просьба `$28`**, каретка гаснет, `$50` := `$32`
и `INC $19` — шаг 2 отсчитывает `$32` картинок, шаг 3 ждёт `$80D9`
(затемнение) и уходит на `$18` := 3, то есть на экран выбора этапа
(`$8009` = `$859D`); при `$5B` = `$1F` — на `$18` := 4.

На негодном (`$96D7`): `$0442` := 0 (каретка гаснет), `$48` := 0,
замолчать, **просьба `$31`**, `$C834` с 7 — это очередной поток 7
(`$CD74`, два куска по 14 плиток в `$2209` и `$2229`: слово «нет»), —
`$50` := `$40`, `$19` := `$0C`. Шаг 12 отсчитывает `$40` картинок, шаг 13
ждёт `$80D9` и возвращает `$19` := 0: экран поднимается заново, и поле
чистое.

## Как экран нарисован

Шаг 0 (`$9693`):

* `$42` := `$0E`, `$43` := `$0F` — два килобайта фона каждый, номер удвоен;
* `$44` := 0, `$45` := 1, `$46` := `$10`, `$47` := `$10` — четыре спрайтовых;
* `$C882` (= `$CB33`) — поток 0, тот, что заливает обе страницы;
* `LDX #$16`, `$C84C` (= `$CB41`) — поток `$16`, то есть одиннадцатый экран
  таблицы `$CBCC` (номер в ней уже удвоен);
* замолчать, **просьба `$43`**, краски `$15` (`$803E`);
* `$51` := 0, `$87` := 0, каретка (`$9914`), `$99EB` чистит `$0680..$068F`,
  `$99F7` — `$0690..$06AF`, и `INC $19`.

Цифры рисует `$9940` — по одной, той очередью, которую кадровое прерывание
выталкивает из `$0300`:

```
A = цифра;  $00:$01 := $99A3[2*A]        ; четыре плитки цифры
$02:$03 := $99D3[2*$51]                  ; куда, старший байт впереди
очередь: 01 | адрес | две плитки | FF    ; верхняя половина
очередь: 01 | адрес + $20 | две плитки | FF   ; нижняя
```

Цифра — это блок два на два. Восемь цифр:

```
0  00 00 00 00      4  E6 E7 F6 F7
1  E0 E1 F0 F1      5  E8 E9 F8 F9
2  E2 E3 F2 F3      6  42 43 45 46
3  E4 E5 F4 F5      7  3D 3E 4D 4E
```

Ноль рисуется пустотой: плитка `$00`. Адреса мест (`$99D3`):

```
2189 218D 2191 2195
2209 220D 2211 2215
2289 228D 2291 2295
```

Плитки цифр — фоновые, из `$0E`/`$0F`, а не спрайтовые: поле стоит в
карте имён, и меняется в ней словом за картинку.

## Показ — шаги 4–11

Второй конец того же экрана: игра **называет** пароль, которым можно
вернуться.  Входят сюда не с заглавного экрана, а из игры.

### Кто сюда посылает — `$D050`

Шаг 11 потока уровня (`$D022`, `work/re/pb2_level_flow.md`) кончается так:

```
D050  A5 9F     LDA $9F          ; сколько ещё раз его вернут
D052  F0 19     BEQ $D06B        ; ни разу -- игра кончилась
D054  C6 9F     DEC $9F          ; иначе жизнь тратится и область строят заново
...
D06B  A9 00     LDA #$00         ; всё сбросить: $79, $AD, $55, $A2, $99, $54,
...                              ; $9C, $27, $9A, $A0, $98, $2C, $2B, $9E,
D090  A9 02     LDA #$02         ; $9D, $1A, $1B
D092  85 18     STA $18          ; экран пароля
D094  A9 04     LDA #$04         ; и его четвёртый шаг -- показ
D096  85 19     STA $19
D098  20 46 D7  JSR $D746        ; таблица мест чистая
D09B  A9 10     LDA #$10
D09D  8D 9A 04  STA $049A
D0A0  4C 33 CB  JMP $CB33        ; поток 0 -- залить обе страницы
```

То есть показ — это **конец игры**: жизни (`$9F`) кончились.  Пароль,
который берут на экране набора, кладёт `$9F` := 2 (`$9755`), и `$D090` даёт
столько же в начале игры.

### Шаг 4 — `$9760`: поднять экран показа

Те же восемь банков, что и у набора (`$42`/`$43` := `$0E`/`$0F`,
`$44`..`$47` := 0, 1, `$10`, `$10`), и дальше:

* краски `$15` (`$803E`) — те же, что у набора;
* `$C882` (= `$CB33`) — поток 0, заливающий обе страницы;
* замолчать (`$C83D`), **просьба `$48`**;
* `$C834` (= `$CCBC`) — очередь `$09`, то есть надпись самого экрана;
* `$50` := 1; ноль в `$79`, `$88`, `$89`, `$87`, `$AD`, `$55`, `$A2`, `$57`,
  `$4F`;
* `$C996` (= `$D8F1`) — метки силы пересчитать; `INC $19`.

Экрана из таблицы `$CBCC` здесь не поднимают вовсе: страница залита нулём, и
всё, что на ней стоит, — очередь `$09`.

### Шаг 5 — `$97A7`: дождаться и поставить каретку

Пока `$C8` не ноль — ничего.  Потом очередь `$08` (две строки выбора) и
каретка через `$985D`.

`$C8` — это **номер, который играет прямо сейчас**: его пишет `$80C3` (просьба
к драйверу) и обнуляет `$813F` (мелодия кончилась).  То есть шаг 4 просит
мелодию конца игры (`$48`), а шаг 5 стоит, пока она не доиграет, — по замеру
сто восемьдесят две картинки.

**Долг Э7.7.** У экрана в порте нет хода к драйверу: `Pb2Sound.want` только
записывает просьбу, а кто её играет, экран не знает.  Поэтому порт здесь не
ждёт вовсе — две строки выбора встают сразу.  Это единственное место, где
показ в порте и показ в картридже расходятся по времени, и стенд Э7.7 именно
его и вычитает при сведении.  Тот же долг уже стоит у шага 10 потока уровня
(`$D017` ждёт `$C8` так же, и `_die` в порте делает шаги 8 и 10 сразу).

### Шаг 6 — `$97B7` → `$983F`: выбор

Читают `$48` (нажатое только что) пятью сдвигами:

* START (бит 4) — `INC $19`;
* SELECT (бит 5) — просьба `$39`, `$4F` := `$4F` EOR 1, и каретку на место.

`$985D` — каретка показа: `$04C6` := `$9870[$4F]` (`$7A` или `$8A`),
`$0508` := `$5A`, `$0442` := `$5A`.  Вид у неё `$5A`, а не `$59`, как у
набора, и `$0400` ей так же не ставят.

### Шаг 7 — `$97BA`: что выбрали

* `$4F` не ноль (нижняя строка) — замолчать, `$99EB` чистит `$0680..$068F`,
  `$99F7` — `$0690..$06AF`, `INC $19`: пароль сейчас покажут;
* `$4F` ноль — замолчать, просьба `$29`, ноль в `$1A`, `$27`, `$98`, `$4F`,
  и `$19` := 2: то же ожидание, которым кончается удачный набор, а за ним
  шаг 3 уводит экран.

### Шаг 8 — `$97E1`: поднять поле и сложить пароль

Ждут затемнения (`$80D9`); потом `$C882`, `$C813` (таблица мест чистая),
`LDX #$16` / `$C84C` — тот же экран `$16`, на котором набирают, `$51` := 0,
и `$9A1C` складывает пароль.

### Как пароль складывают — `$9A1C`

Обратный ход того же кодека, что и приговор, и ровно теми же таблицами.

**Первое — разложить девять бит по местам** (`$9A25`, и байт в байт та же
ветка `$9A58` для `$5B` = `$1F`):

```
$0687 := ($5B & $03) << 1
$0689 := ($5B & $0C) >> 1
$068B := ($5B & $10) >> 2
$0688 := ($56 & $03) << 1
$068A := ($56 & $0C) >> 1
```

Остальные семь мест `$0680..$068B` остаются нулями — их обнулил `$99EB` на
шаге 7, — и четыре байта очков тоже: у этой игры они всегда нули.

**Второе — сумма** (`$9A8A`).  Складывают все двенадцать `$0680..$068B` в
один байт и раскладывают его младшие семь бит по младшим битам тех же шести
старших мест:

```
$0686 |= сумма & $01        $0689 |= (сумма & $08) >> 3
$0687 |= (сумма & $02) >> 1  $068A |= (сумма & $10) >> 4
$0688 |= (сумма & $04) >> 2  $068B |= (сумма & $60) >> 5
```

Это та самая сумма, которую приговор проверяет в `$9C2B`.

**Третье — перестановка** (`$9B21`): `$0690[i] := $0680[perm[i]]`, где `perm`
— слово из `$9B74` по `$5B` (шестнадцать слов, четыре разных адреса по
кругу), а для `$5B` = `$1F` — особая таблица `$9B68`.  Приговор делает то же
наоборот (`$9BFC`).

**Четвёртое — сдвиг** (`$9AE9`): `$0690[i] := ($9AFD[i] + $0690[i]) & 7`.
Приговор вычитает (`$9B09`).

### Шаг 9 — `$97FC`: выписать двенадцать цифр

По цифре на картинку: `$9872` берёт `$0690[$51]` и отдаёт её `$9940`, тому
же, что рисует цифру при наборе.  `INC $51`; на двенадцатой — краски `$15`
ещё раз и `INC $19`.

### Шаг 10 — `$9810`: стоять, пока не START

`$48 & $10` — и `INC $19`.

### Шаг 11 — `$981A`: всё сначала

Ждут затемнения; потом ноль в `$18`, `$19`, `$5B`, `$56`, `$2B`, `$2C`,
`$57`, `$53` и `$C813`.  `$18` := 0 — это заглавный экран.

## Два места, где чтение пришлось поправить

**Затемнение `$80D9` выбрасывает тон.** `$80EE` — это `AND #$30`, и уже
потом `SBC #$10`; результат кладут обратно. То есть первый же шаг гашения
обесцвечивает весь экран, а дальше идёт чистая яркость: `$37` идёт `$20`,
`$10`, `$0F`, а не `$27`, `$17`, `$07`. Порт сначала вычитал `$10`,
сохраняя тон, и стенд поймал это на 88-й картинке отказа — тридцать два
байта тени (`$03E0..$03FF`) он сверяет каждую картинку. Поправлено и в
`work/re/pb2_map.md`, где было сказано просто «отнимает `$10`».

**Подъём заново — это отдельная картинка.** Шаг 13 не поднимает экран сам:
он кладёт `$19` := 0, и шаг 0 идёт уже следующей картинкой. Порт сначала
делал и то и другое сразу и уходил на две картинки вперёд.

* `main.gd` — проводка: вторая строка заглавного экрана (`$8018`) ведёт
  сюда, а взятый пароль открывает первую область названного этапа и кладёт
  `$5B`/`$56` в `Pb2Status`, минуя файл: только что набранный пароль —
  слово более новое, а записывает его уже присмотр Э7.3;
* приёмка — `work/extract/verify_pb2_pass.py`. Экран берут так, как берёт
  его игрок: стенд играет заглавный экран, ждёт первое ожидание, водит
  каретку на вторую строку и жмёт START, и только тогда начинается прогон.
  Сверяется всё, что экран держит: шаг `$19`, место каретки `$51`, остаток
  ожидания `$50`, двенадцать цифр `$0690..$069B`, разложенное поле
  `$0680..$068B`, шесть найденных байт `$06A0..$06A5`, `$5B`/`$56`, три
  поля каретки, тридцать два байта тени палитры, просьбы к звуку, экран и
  шаг выхода — и картинка точка в точку. На выходе сверяется и проводка:
  `$53`/`$9C`/`$5B`/`$56`, как их оставил картридж, против того, с чем
  движок начал игру.

  Пароли стенд строит сам, обратным ходом по тем же пяти проверкам, и
  **картридж их принимает** — это и есть доказательство, что кодек прочтён
  верно: `$00`/0 и `$03`/5 и `$0F`/`$F` уходят на экран 3, `$1F`/`$F` — на
  экран 4.

  Выравнивание не считают руками: стенд ищет первую картинку, где `$18` = 2
  и `$19` = 1, и следующая за ней — нулевая строка порта. `$1C` порту
  отдают из записи, потому что гашение считает по нему, а счёта картинок
  между экранами порт не держит (это единственное число, которое стенд
  порту даёт).
