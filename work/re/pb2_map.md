# Карта выбора этапа Power Blade 2

Разобрано в Э3.8 (приёмка Э3), когда прогон «движок проходит игру сам»
упёрся в то, что после босса игра идёт **не** на следующий этап.
Поток вокруг карты — в `work/re/pb2_level_flow.md`, раздел «Что после босса».

## Как до неё доходят

`$18` — «что показывать».  `$ED62` (банк 15) читает его и уходит по таблице из
девяти адресов в `$ED69`; пятая запись — `$EE98`:

```
EE98  20 FB EE  JSR $EEFB        ; LDY #$30 / JMP $ECA7 -- пара банков 0
EE9B  4C 24 80  JMP $8024        ; в нулевой паре: JMP $9EC8
```

`$18 := 5` ставят два места: `$88F0` — когда босс отжил своё, и `$8912` —
когда последний этап уже пройден.

## Что из этого нужно движку

Минимум, без которого игру нельзя пройти от заставки до конца, — шаги 22 и 32:
куда карта отдаёт управление.  Всё остальное (ход героя по карте, полосы,
звуки) — картинка.

## `$80D9` — затемнение

Того, чего ждут шаги 0, 7, 22, 23 и 31, — это гашение экрана.  `$03E0..$03FF` —
тень палитры; каждую шестнадцатую картинку `$80D9` отнимает `$10` у каждого из
тридцати двух байт, пока все не станут `$0F` (чёрный), и только тогда
возвращает перенос установленным.

```
80D9  20 06 81  JSR $8106        ; все ли уже $0F?  тогда SEC
80DF  A5 1C     LDA $1C
80E1  29 0F     AND #$0F         ; раз в шестнадцать картинок
80E5  A2 00     LDX #$00
80E7  BD E0 03  LDA $03E0,X      ; каждый байт тени
80EA  C9 0F     CMP #$0F         ; уже чёрный -- не трогать
80EE  29 30     AND #$30         ; яркость кончилась -- сразу в $0F
80F6  38 E9 10  SEC / SBC #$10   ; иначе на ступень темнее
```

## Что это на самом деле

Это **не меню выбора этапа**, а проход между этапами: герой идёт по карте
(`$0508` растёт, кадр ходьбы из `$9FDD`), экран гаснет, и шаг 22 отдаёт
управление дальше — `$18`/`$19` := 3/`$14`, то есть `$859D` в той же нулевой
паре.  Само меню, где игрок тычет в этап, живёт там.

## Экран 3 (`$859D`) — выбор этапа

Карта отдаёт управление сюда: `$18`/`$19` := 3/`$14`.  Здесь такой же список
шагов по `$19`, 24 штуки, таблица в `$85A2`.  Дорога после карты:

| `$19` | адрес | что делает |
|---|---|---|
| 20 | `$8838` | ставит сцену: по `$53` берёт запись из `$89FA` (три байта — экран и левый край), кладёт героя (объект 0) в `$80`,`$C8` и вывеску (объект 1, вид `$50`) в `$18`; `$22` := `$53` |
| 21 | `$8881` | включает картинку и уходит на шаг 12 |
| 12 | `$871C` | **сам выбор** |
| 15 | `$87A7` | разворот на месте: `$05A2` тикает вниз, потом бит `$40` в `$042C` переворачивается, назад на 12 |
| 16 | `$87C0` | ходьба: `$05CE` тикает вниз, `$0508` едет на два пункта в сторону взгляда |
| 18 | `$8816` | гашение, потом `$53` := `$22`, `$9C` := 0 |
| 19 | `$882F` | `$19` := 0, `$1A` := 0, `INC $18` — то есть на экран 4, в этап |

### Шаг 12 — что нажимает игрок

```
871C  LDX #$00 / JSR $C837          ; герой стоит
8721  LDA $48 / AND #$10  -> Start  ; выбрал
8727  LDA $48 / LSR       -> вправо ; следующий этап
872C           LSR       -> влево   ; предыдущий
```

* **Start**: `JSR $8969` — можно ли туда.  Нельзя — ничего не происходит.
  Можно: `$19` := 18 (гашение), вид героя `$0442` := `$53`, звук `$29`.
* **Вправо**: если герой смотрит влево (`$042C` бит `$40`) — сперва разворот
  (`$0442` := `$54`, `$05A2` := 8, `$19` := 15, звук `$36`).  Если уже смотрит
  вправо — `INC $22` и шаг вперёд, но не дальше 3 (а если `$5B` == `$0F`, то
  есть первые четыре этапа пройдены, то не дальше 4).
* **Влево**: то же зеркально, `DEC $22`, не ниже нуля.

### `$8969` — пускают ли на этот этап

```
LDY $22 / LDA $8969+$14,Y   ; бит этапа: 01 02 04 08 10 20 40 80
AND $5B / BEQ пускают       ; этап ещё не пройден -- иди
AND $56 / BEQ пускают       ; пройден, но костюм оттуда ещё не взят
SEC                          ; иначе отказ
```

## `$5B` и `$56` — что пройдено

* `$5B` — **биты пройденных этапов**.  Ставит их `$BE22` (банк 11):
  `LDY $53 / LDA $BE36,Y / ORA $5B / STA $5B`, где `$BE36` = `01 02 04 08 10
  20 40 80`.  Зовут её ровно из одного места — `$88F0`, то есть сразу после
  павшего босса.  При включении игры `$5B` обнуляется ($01826), а из пароля
  восстанавливается из `$06A0` (`CMP #$1F` — все пять).
* `$56` — тем же битом, но `$BE2C`, и ещё `$F591` (банк 7) переворачивает бит
  по `$B5CD,$53`.  Похоже на «костюм с этого этапа уже взят»: пройденный этап
  без этого бита в выборе всё ещё открыт.

## Как экран выбора едет

`$FD` и `$FF` — это прокрутка: `$FD` коарс-икс, `$A0A4` и `$A4D5` прибавляют
к нему `$10` (шестнадцать точек) за шаг, а при переполнении переворачивают
нулевой бит `$FF` — тени `$2000`, то есть меняют экран.  Значит задник выбора
широкий и едет вбок, ровно как карта уровня, а герой ходит вдоль вывесок.

Шаг 20 берёт начальную прокрутку из записи по `$53` (`$89FA` → пять записей
по три байта, `$8A04`..`$8A12`): `$FD` = `60 A0 E0 20 60`, `$FF` = `A8 A8 A8
A9 A9`, третий байт — место вывески (`$0509` = `B8 98 78 58 38`).

## Откуда берётся сам экран

Две разные вещи, и раньше они были записаны как одна.

**Цвета.** `$8044` (`$803E` = он же плюс «показать») — это загрузчик
**палитры**, а не задника: он кладёт тридцать два байта в `$03E0..$03FF`,
откуда `$80AB` отправляет их в `$3F00`.

```
8044  STA $93 / ASL / TAY
8048  LDA $811F,Y / $8120,Y -> $08/$09     ; запись экрана: восемь байт
8057  LDY $0A / LDA ($08),Y / TAY          ; байт записи -- номер четвёрки
805C  LDA $82F5,Y -> $0B / LDA $837D,Y -> $0C
8066  LDA #$0F / JSR $80A6                 ; $0F, а за ним три цвета из ($0B)
```

Восемь четвёрок по четыре байта и есть тридцать два. Шаг 0 экрана 3 просит
палитру `$22`, шаг 21 — `$03`.

**Плитки.** Их кладёт `$C84C` (`$CB41`), которому дают номер в `X`; шаг 0
экрана 3 даёт `$18`. Номер уже удвоен: пара байт берётся из `$CBCC,X` и
`$CBCD,X`, то есть запись номер двенадцать — `$8B0F`. При `X >= 2` сначала
переключают пару банков `Y = $38`, а `$ECAB` берёт от неё только младшую
тетраду — это банки **8/9**.

Дальше `$CB59` читает поток:

* первые два байта записи — адрес в `$2006` (сначала старший, потом младший);
* `$FF` — конец;
* `$7F` — начать сначала с нового адреса (ещё два байта);
* байт со старшим битом — `N = байт AND $7F` плиток подряд, как есть;
* байт без старшего бита — столько же раз один и тот же следующий байт.

`$CA24` между кусками двигает указатель на прочитанное.

Поток экрана выбора (`X = $18`, `$8B0F` в банке 8) разобран: четыре куска —
`$20A0`, `$23C8`, `$24A0`, `$27C8`, всего 816 байт. То есть **полоса строк
5..16 на обеих страницах имён** и их цвета; остальное поле не пишется вовсе.
Это и сходится с тем, что полоса едет вбок, а страницы перекидывает бит 0
`$FF`.

### Экранов на выборе два, а не один

В экран 3 входят с двух сторон, и каждая рисует своё.

**Сначала (`$19` = 0, `$85D8`)** — после заставки. Кладут полосу `X = $18`
(те самые 816 байт), палитру `$22`, плитки `$42`/`$43` := `$1A`/`$1B` и
`$44`/`$45` := `$3C`/`$3D`, героя видом `$5B` в `$80`,`$60`, и `$51` := `$D0`
на выдержку. Поле вокруг полосы остаётся тем, что осталось от заставки.

**После этапа (`$19` = `$14`, `$8838` → `$88CE`)** — дорога с карты. Здесь
кладут **весь** экран `X = $08` (`$82F2`: `$2000` и `$2400` по 896 байт плюс
по 56 байт цвета — обе страницы имён целиком), плитки `$42`/`$43` := `$24`/
`$25` и `$44`/`$45` := `$46`/`$47`, прокрутку `$FD` := `$20`, а потом уже
`$8838` ставит сцену по `$53`:

```
883E  LDA $53 / STA $22 / ASL / TAY    ; запись из $89FA -> $8A04..$8A12
8850  ($00),0 -> $FD                   ; коарс-икс
8855  ($00),1 -> $FF                   ; тень $2000 (бит 0 -- какая страница)
885A  ($00),2 -> $0509                 ; икс вывески
885F  $0443 := $50                     ; объект 1 -- вывеска
8866  $04C7 := $18                     ; её игрек
886F  X=0 / $C83A                      ; герой встал
8874  $0508 := $80 / $04C6 := $C8      ; герой в середине, ниже вывески
```

Шаг 21 (`$8881`) включает картинку: банки `$C83D`, `$C81C` с `#$44`,
`$87` := 3, `$89`/`$88` := `$A8`/`$00`, `$19` := 12 и палитра 3 через `$803E`.

### Пройденные этапы дорисовываются поверх (`$8A13`)

Сразу за экраном `$08` идёт `$8A13`: он проходит четыре младших бита `$5B`
и на каждый поставленный зовёт `$8A51` — заплатку восемь на шестнадцать
плиток поверх вывески этого этапа.

* куда класть плитки — `$8ADA` по два байта, старший первым:
  `$2018`, `$2400`, `$2408`, `$2410`;
* куда класть цвета — `$8AE2`: `$23C6`, `$27C0`, `$27C2`, `$27C4`, `$27C6`;
* сами плитки — `$8AEC`, 128 байт: `$8A8C` пишет по восемь и прибавляет `$20`
  к адресу, то есть столбик шириной восемь на шестнадцать строк.  Верхние
  восемь строк пустые, нижние — картинка;
* цвета — `$8B6C`, восемь байт (`00 00 00 00 FF FF 0F 0F`), по два за раз
  с шагом `$08`.

А когда `$5B` == `$0F` (первые четыре этапа пройдены), `$8A4B` кладёт ещё
пятую запись — только цвета `$8B74` (`00 03 30 00 30 C0 03 0C`) в `$27C6`.
Это и открывает пятый этап: `$8969` пускает на него, а картинка проявляется
цветами.

Это и есть работа Э3.10b: разобрать поток в сетку 32x30 и нарисовать её теми
же банками знаков (`$42`..`$45`, у экрана выбора — `$1A`/`$1B` и `$3C`/`$3D`)
и той же палитрой.

## Чего ещё не разобрано
* `$A0B4`, `$A73E`, `$A7BC`, `$A7E0`, `$A770`, `$A6F4` — рисование самой карты.
* `$A182` — счётчик шага героя по карте: `$05E4` тикает вниз, `$05FA` считает
  до трёх, длины из `$A1A1` (`30 40 38`), на каждом шаге звук `#$2D`.
* Как карта узнаёт, какие этапы уже пройдены (`$5B`).  Шаг 32 ставит `$53` := 5
  наглухо — значит эта ветка и есть дорога на последний этап, а не общий выход.
* `$A1A4` — такая же таблица по `$19`, но для `$18` = 7: конец игры.
