# Поток уровня Power Blade 2

Как этап идёт сам собой: из области в область, к боссу, и обратно к началу,
когда герой погиб. Всё, что здесь записано, снято с картриджа —
дизассемблером и трассой эмулятора.

## `$1A` — шаг самого уровня

Каждый кадр `$CDCE` берёт `$1A` и по таблице слов за `JSR $CA0B` (адрес
`$CDD3`) выбирает работу кадра. Проверки границ у `$CA0B` нет.

| `$1A` | адрес | что это |
|---|---|---|
| 0 | `$CDED` | начало этапа: `$66:$67 := 0`, `$27 := 0`, `$85 := 6`, `$45 := $11`, дальше 1 |
| 1 | `$CE11` | `$D650` |
| 2 | `$CE14` | подготовка: `$E23F` (запись области), `$DDE1`, `$D32A`, `$D125`, музыка |
| 3 | `$CE91` | `$DFDF` — начать рисовать экран |
| 4 | `$CE97` | `$DFF0` — рисовать, пока не ответит 1; потом `$2A := 0`, дальше 5 |
| 5 | `$CED2` | **уровень играется**: вода/лава (`$29`) двигается только здесь |
| 6 | `$CF3C` | уровень перестраивают: дождаться затемнения, собрать всё заново, `$27 := 0`, `$1A := 3` |
| 7 | `$CFBA` | то же, но `$27 := 1` |
| 8..11 | `$CFF7`, `$D010`, `$D017`, `$D022` | смерть: см. ниже |
| 12 | `$CFB4` | `$CE25` (музыка) и дальше как 6 |

## Сколько областей в этапе — `$D6CD`

`$D6BC` (переходник `$C894`) кладёт `$9C` в `$17` и сравнивает с
`$D6CD[$53]`; перенос взведён **только при равенстве**. `$D6C0` (`$C8D0`) —
то же самое, но `$17` уже положил вызывающий.

```
$D6CD:  07 08 07 07 0A 0E 0C        ; этапы 0..6
```

Это и есть число проходимых областей. Равенство после `INC $9C` значит:
областей больше нет, дальше комната босса.

## Где герой встаёт, когда область открыли — `$F04C`

Банк 15. Один байт на область, семь таблиц по указателям в `$F0A4`
(`$F0B2`, `$F0B9`, `$F0C1`, `$F0C8`, `$F0CF`, `$F0D9`, `$F0E7`):

```
A := 6, если $79 не ноль, иначе $53      ; седьмая таблица -- комнаты боссов
$00:$01 := $F0A4[2*A]
$02 := ($00)[$9C]
$04C6 := ($02 AND $F0) OR $0F            ; вниз: старший полубайт и 15 под ним
$0508 := ($02 << 4) AND $F0              ; вбок: младший полубайт целой клеткой
если $0508 > $80: $042C := $042C OR $40  ; смотрит влево
иначе:            $042C := $042C AND $BF
```

Особый случай: этап 4, область 3, `$AD` не ноль — вбок берут `$09`, а не
байт таблицы.

Проверено трассой: этап 0, область 0 — байт `$8E`, и картридж ставит героя в
`x=224, y=143`; после двери из области 0 в область 1 — байт `$8E`, `x=224,
y=143`, вид с `$0090`. Совпадает с записью области (`$E23F`, байты 3 и 4).

## Запись области — `$E23F`

Банк 15, банковая пара 6/7 под ней. Четырнадцать байт: `$97` ось, `$AE` вид
(идёт в `$87`), `$73`, `$66:$67` где начинается вид, `$59:$5A` докуда он
доходит, `$42`, `$43`, `$46`, `$47`, `$FC`, `$016D`, `$016E`. Таблицу
таблиц выбирают так же, как в `$F04C`: `$79` не ноль — берут седьмую.

## Тип `$04` — дверь в конце области

Банк 10, `$8542`. Пятьдесят две записи в игре. Таблица состояний за
`JSR $C97E`: `$8551`, `$8449`, `$85FD`, `$864A`, `$86D2`, `$86E7`.

**0 (`$8551`)** — стать собой:

```
если $049A,X не ноль и $BE36[$53] AND $5B: убрать ($C810)
$0416,X := $10                            ; короб героя 8x8
$00:$01 := $8587[$53]
$05FA,X := ($00)[2*$9C]                   ; куда на экране рисовать проём
$0610,X := ($00)[2*$9C + 1]
состояние := 1
```

`$BE36` — это просто `01 02 04 08 10 20 40 80`, то есть бит этапа; `$5B` —
какие этапы уже пройдены. То есть дверь с жизнью в записи на втором проходе
пройденного этапа не стоит вовсе.

**1 (`$8449`)** — `RTS`. Будит её `$B5A5`: касание героя с чем-нибудь, у чего
в метке бит `$10`, кладёт `$058C,X := $02` и `$0416,X := $80`.

**2 (`$85FD`)** — уход:

```
$27 := 4; $042C := $042C AND $7F; $2A := 1; $4E := 1; $58 := 1
если $53 == 5 и $9C == 0: $0442 := 0 и сразу закрываться
если $87 равен 6, 9 или 4: сразу закрываться
$17 := $9C + 1; JSR $C8D0; если равно (последняя) -- JSR $C83D
состояние := 3
```

Закрываться сразу (`$863F`) — это `$0626,X := $20`, состояние := 5.

**3 (`$864A`)** — открывание, ряд проёма в четыре кадра:

```
INC $0626,X
каждый восьмой -- звук $32
если $0626,X AND 3 не ноль: выход
если $05E4,X нечётен и не равен 7:
        $0610:$05FA -= $20 (с заёмом), и если стало $1F:$E0 -- то $23:$A0
INC $05E4,X
состояние := 4
```

**4 (`$86D2`)** — восемь рядов и хватит: `$05E4,X == 8` — `$0626,X := $20` и
состояние := 5; иначе состояние := 3.

**5 (`$86E7`)** — закрывание:

```
DEC $0626,X; пока не ноль -- выход
$1A := 6                                  ; уровень перестроить
INC $9C
JSR $C894; если равно (областей больше нет):
        $79 := 1; $AD := 2
        $9C := 0, если $53 == 5, иначе $9C := $53
убрать себя ($C810)
```

Трасса (этап 0, область 0, дверь открыта поком в её состояние): `$0626`
идёт `01`..`$20`, `$05E4` `00`..`08`, `$05FA:$0610` `25 E0`, `25 C0`,
`25 A0`, `25 80`; на кадре 192 `$9C` становится 1 и `$1A` — 6; на кадре 254
`$1A` := 3 и вид := `$0090`; на кадре 288 герой стоит в `x=224, y=143`.

## Тип `$03` — прямо к боссу

Банк 10, `$840A`. Четыре записи на всю игру: 0:4, 1:3, 2:2, 3:4. Таблица
состояний за `JSR $C97E`: `$8419`, `$8449`, `$844A`, `$8477`, `$84D0`,
`$84F1`. Устроено как дверь, только открывает не соседнюю область, а
комнату босса.

**0 (`$8419`)** — стать собой:

```
если $BE36[$53] AND $56: убрать ($C810)   ; этап уже пройден
$0416,X := $10                            ; короб героя 8x8
$05FA,X := $843D[2*$53]                   ; куда на экране рисовать проход
$0610,X := $843D[2*$53 + 1]
состояние := 1
```

```
$843D:  21 8E  21 8E  25 8E  24 CE  25 0E  20 8E     ; этапы 0..5
```

**1 (`$8449`)** — `RTS`; будит `$B5A5`, как и дверь.

**2 (`$844A`)** — взять героя:

```
$27 := 4; $042C := $042C AND $7F
$0442 := 4                                ; поза, в которой он едет вверх
$0508 := $0508,X                          ; встать ровно туда, где стоит вещь
$4E := 1; $58 := 1; $05E4,X := 0
JSR $C83D; звук $2C; состояние := 3
```

**3 (`$8477`)** — рисование: шестнадцать рядов подряд из таблицы `$850A`
(четыре байта на ряд, `$10:$11` шагает по `$20`), потом `INC $05E4,X`,
`$0626,X := $10` и состояние := 4.

**4 (`$84D0`)**:

```
если $05E4,X == 2: $0442 := 0             ; из позы обратно
если $05E4,X == 4: состояние := 5
иначе DEC $0626,X; на нуле состояние := 3
```

**5 (`$84F1`)** — если `$CC` ноль: `$1A := 6`, `$79 := 1`,
`$9C := $53 + 6`, убрать себя.

То есть комнаты босса нумеруются в шестом этапе так: дверь `$04` последней
проходимой области ведёт в `6:$53` (тип `$05`), а `$03` — в `6:$53+6`
(тип `$06`).

## Смерть и возвращение — `$1A` 8..11

Из трассы (герой без здоровья): `$1A` идёт 8, через кадр 9, через 199 кадров
10, через кадр 11, через 50 кадров — возвращение.

`$D022` (шаг 11) ждёт затемнения (`$ED11`) и потом:

```
$54 := 0; $9A := 0; $79 := 0
$D5C1; $D58D; $45 := $11
если $55 не ноль: DEC $55                 ; ступень лезвия ниже
если $99 не ноль: DEC $99                 ; на один бросок меньше
если $A2 не ноль: DEC $A2                 ; второе лезвие теряется
$D8F1                                     ; метки силы пересчитать
если $9F (жизни) не ноль:
        DEC $9F; $D4C5; $049A := $10; $D4ED; $D7AB; $CE45; $CE25
        и дальше тем же телом, что и шаг 6 ($CF42)
иначе:
        всё сбросить: $79, $AD, $55, $A2, $99, $54, $9C, $27, $9A, $A0,
        $98, $2C, $2B, $9E, $9D, $1A, $1B := 0; $18 := 2; $19 := 4;
        $D746; $049A := $10; $CB33
```

То есть возвращение после смерти — это та же перестройка уровня, что и после
двери, только область остаётся своя. Где герой встанет, решает всё тот же
`$F04C`.

## Что после босса — `$88F0` (банк 10)

Когда босс отжил все шесть состояний умирания, `$88EB` доходит до `$88F0`:

```
88F0  A5 53     LDA $53          ; какой этап
88F2  C9 05     CMP #$05
88F4  F0 27     BEQ $891D        ; пятый -- у него своя цепочка
88F6  A9 00     LDA #$00
88F8  85 27     STA $27          ; уровень снова играют
88FA  85 79     STA $79          ; следующая область -- не комната босса
88FC  85 AD     STA $AD          ; половина этапа -- снова ходовая
88FE  20 22 BE  JSR $BE22
8901  A5 53     LDA $53
8903  C9 04     CMP #$04
8905  D0 0B     BNE $8912
8907  A9 05     LDA #$05         ; $18 := 5 -- карта выбора этапа
8909  85 18     STA $18
890B  A9 17     LDA #$17         ; $19 := $17 -- своя строка для пятого этапа
890D  85 19     STA $19
890F  4C 13 C8  JMP $C813
8912  A9 05     LDA #$05
8914  85 18     STA $18
8916  A9 00     LDA #$00
8918  85 19     STA $19
891B  4C 13 C8  JMP $C813
```

То есть **после босса игра идёт не на следующий этап, а на карту**: пара
`$18`/`$19` — это «что показывать дальше», и пятёрка в `$18` и есть карта
выбора этапа.  Следующий этап выбирает игрок.

Последний этап, `$53` равно пяти, идёт своей цепочкой:

```
891D  E6 9C     INC $9C          ; следующая комната того же шестого стола
891F  A5 9C     LDA $9C
8921  C9 05     CMP #$05
8923  F0 0B     BEQ $8930        ; пятая -- конец игры ($18 := 6, $19 := $1F)
8925  C9 06     CMP #$06
8927  F0 E9     BEQ $8912        ; шестая -- на карту
8929  A9 06     LDA #$06
892B  85 1A     STA $1A          ; иначе просто собрать следующую комнату
892D  4C 13 C8  JMP $C813
```

В движке этого перехода нет: `_die_done` ставит `$1A := 6`, и область
собирается заново — то есть комната босса открывается сама себе.  Прогон Э3.8
(`verify_run.py`) обходит это своим ломом и пишет отдельной строкой «на карту,
и дальше на N:0».  **Долг: карта выбора этапа как поток.**

## Где живёт карта выбора этапа

`$18` — это «что показывать»: `$ED62` (банк 15) читает его и уходит по таблице
из девяти адресов в `$ED69`.

```
ED62  E6 1C     INC $1C
ED64  A5 18     LDA $18
ED66  20 0B CA  JSR $CA0B        ; уйти по таблице, что лежит следом
ED69  7B ED  31 EE  51 EE  57 EE  5D EE  98 EE  9E EE  A4 EE  AA EE
;      0      1      2      3      4      5      6      7      8
```

Пятая — `$EE98`:

```
EE98  20 FB EE  JSR $EEFB        ; $EEFB: LDY #$30 / JMP $ECA7 -- пара банков 0
EE9B  4C 24 80  JMP $8024        ; в нулевой паре: JMP $9EC8
```

Итого: **карта выбора этапа — это `$9EC8` в нулевой паре банков**
(`work/re/pair0.asm`), а `$19` внутри неё — номер шага.  `$EEBA` ставит `$18` и
обнуляет `$19`; `$EEB7` двигает `$19` на один; `$EEB0` двигает `$18`.

Сама карта -- такая же машина состояний, как всё в этой игре: `$9EC8` читает
`$19` и уходит по таблице из тридцати трёх адресов, что лежит следом.

```
9EC8  A5 19     LDA $19
9ECA  20 4F C8  JSR $C84F        ; уйти по таблице, что лежит следом
9ECD  0F 9F  56 9F  E6 A5  5D 9F  62 9F  99 A5  AA A5  B5 A5
9EDD  0B A6  32 A6  69 9F  E6 A5  70 9F  7B 9F  95 9F  E1 9F
9EED  B5 A5  32 A6  FB 9F  08 A0  99 A5  AA A5  18 A0  43 A0
9EFD  6D A0  E6 A5  74 A0  AA A5  88 A0  99 A5  AA A5  B5 A5
9F0D  8F A0
```

Разбор этих тридцати трёх шагов -- работа отдельного этапа; здесь записано
только, где они лежат.

Тем же путём достаются и остальные экраны: 0 — заставка (`$ED7B`, прямо в
пятнадцатом банке), 1 — `$EE31`, 2 — `$8018`, 3 — `$8009`, 4 — сам уровень
(`$EE5D`, оттуда `$CDB8`), 6 — `$802D`, 7 — `$8027`, 8 — `$800C`.

## Что отсюда взято в движок

* `game/data/pb2/levels/stageN.json`: у каждой области `start` (`x`, `y`,
  `face`) из `$F04C` и `door` (два байта) из `$8587`; в `index.json` у
  каждого этапа `walk` из `$D6CD`.
* `index.json` у каждого этапа ещё и `boss_door` — пара байт из `$843D`.
* `game/src/pb2_objects.gd`: умы `$04` и `$03` целиком, поля `area` (`$9C`),
  `boss` (`$79`), `phase` (`$AD`), `cleared` (`$5B`), `live` (`$1A`).
* `game/src/main.gd`: `_next_area` и `_die`.
* Сверка: `work/extract/verify_flow.py`.

## Чего ещё нет

* `$79` в движке живёт только до перестройки: комнаты босса дверей не
  содержат, так что пока это не видно, но при Э3.6 флаг должен пережить
  перестройку.
* `$5B` (пройденные этапы) движок не ставит — двери с жизнью в записи всегда
  на месте.  На картридже его ставит `$BE22` (банк 11, `ORA` бита этапа из
  `$BE36`), и зовут её из единственного места — `$88F0`, сразу после босса.
  См. `pb2_map.md`.
* Переход после босса (`$88F0`, `$18` := 5 — карта выбора этапа) не
  перенесён: движок собирает комнату босса заново.
* Шаги `$1A` 8..11 движок проходит мгновенно: у них своё время (199 и 50
  кадров) и своё затемнение, которое ещё не сделано.
