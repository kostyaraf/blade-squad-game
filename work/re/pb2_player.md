# Power Blade 2 — как устроен герой

Всё ниже снято с картриджа: адреса — из трассы эмулятора (`work/tools/nesemu`),
числа — из кода банковой пары 8/9 и подтверждены измерением
(`work/tools/pb2_probe.py`). Ни одно значение здесь не «подобрано на глаз».

## 1. Где герой живёт в памяти

Объекты игры лежат в одной таблице на 22 ячейки. Поле *f* объекта *n* —
по адресу `$0400 + 22*f + n`. Герой — ячейка 0.

| поле | адрес (герой) | что это |
|------|---------------|---------|
| f1  | `$0416` | состояние: `00` стоит, `02` идёт, `01` в воздухе, `08` присел, `10` подкат, бит7 — идёт удар |
| f2  | `$042C` | сторона: бит6 = смотрит влево |
| f3  | `$0442` | номер метаспрайта (поза) |
| f5  | `$046E` | счётчик кадров анимации |
| f6  | `$0484` | кадр анимации 1..4 |
| f8:f9:f10 | `$04B0`:`$04C6`:`$04DC` | Y: старший байт : пиксели : дробь (1/256) |
| f11:f12:f13 | `$04F2`:`$0508`:`$051E` | X: старший байт : пиксели : дробь (1/256) |
| f14:f15 | `$0534`:`$054A` | скорость по Y (старший:младший), 1/256 пикселя за кадр |
| f16:f17 | `$0560`:`$0576` | скорость по X |
| f18 | `$058C` | номер обработчика (см. §2) |
| f19 | `$05A2` | делитель шага: бит7 — делить на 4, иначе на 2; бит6 + `$9A`=2 — не делить |
| f21:f22 | `$05CE`:`$05E4` | накопитель сдвига по X **за этот кадр** (младший:старший) |
| f23:f24 | `$05FA`:`$0610` | накопитель сдвига по Y за этот кадр |
| f26 | `$063C` | флаги «сквозь стены» этого кадра |

Координата хранится **относительно камеры**: когда камера едет, `$D389`
(и `$D35D` для Y) вычитает сдвиг из позиций всех объектов. Абсолютное
положение = положение камеры + это.

Каждый кадр `$8E32` обнуляет f21..f24, f19 и f26: это временные накопители,
а не скорость.

## 2. Обработчики (f18)

`$8E56` берёт f18 и прыгает по таблице `$8E66`/`$8E89` (35 входов, банк 8).

| f18 | адрес | что |
|-----|-------|-----|
| 4 | `$8EC1` | обычное состояние: стоит / идёт / прыгает / падает |
| 5 | `$8F8C` | присел |
| 7 | `$9036` | подкат |
| 8, 9 | `$91B5`, `$9193` | лестница |
| 17 | `$94A9` | зацепился (вход из `$A003`) |

Кнопки лежат в `$4A` (удержание) и `$48` (нажатие в этом кадре), порядок битов
обычный для NES: бит7 A, бит6 B, бит3 вверх, бит2 вниз, бит1 влево, бит0 вправо.

## 3. Движение по горизонтали

`$A08D` разбирает нажатия, `$A06D`/`$A0A2`/`$A0D4` задают ускорение,
`$B23A` — «разгонять к пределу с шагом», параметры лежат **прямо за JSR**
четырьмя байтами: предел (старший, младший), шаг (старший, младший).

| случай | предел | шаг |
|--------|--------|-----|
| держат вправо, скорость 0..1 | `+1.0` | `+0.5` |
| держат вправо, скорость 1..4 | `+1.0` | `-0.015625` |
| держат вправо, скорость ≥ 4 | `+1.0` | `-0.125` |
| держат влево | зеркально | зеркально |
| ничего не держат | `0` | `0.5` к нулю |

То есть **шаг ходьбы ровно 1 пиксель за кадр**, первый кадр — полпикселя.
Измерено: `vX` = `$FF80`, дальше `$FF00`, и `$0508` меняется на 1 каждый кадр.

Дальше `$B1FA` добавляет скорость в накопитель кадра, а `$A056` пробует
сдвинуть героя: `$ACBA` проверяет стену, при упоре `$B2F1` обнуляет скорость.

## 4. Прыжок и тяжесть

* импульс прыжка — `$9FE2`: `vY = $FB00` = **−5.0 пикселя за кадр**;
* тяжесть — `$91F3`: `vY += $0032` = **+0.1953125** каждый кадр;
* если кнопка A **отпущена** (бит7 `$4A` снят), `$920B` добавляет ещё
  `$0070` = **+0.4375**, то есть высота прыжка управляется удержанием;
* предел падения — `$9236`: **5.0** пикселя за кадр; в «медленном» режиме
  (`$05A2` бит6 и `$9A`=2) — **2.0**;
* маленький толчок вверх `$9FDB`: `vY = $FFCE` = −0.1953.

Позы: `$18` (24) — вверх, `$19` (25) — вниз.

## 5. Тело героя

Размер тела зависит от позы: `$AEBD`/`$AEEC` — таблица указателей на описания.

*Для проверки стены* описание = `[полуширина, ряд1, ряд2, ряд3]`, ноль обрывает
список. Обычная поза (индекс 1, 24, 42) — `$AF1E`: **полуширина 5** (влево −6,
вправо +5) и три ряда: `0` (ноги), `−14`, `−27` (голова).
Присел (индекс 5) — `$AF2D`: полуширина 5, ряды `0` и `−13`.

*Для проверки пола и потолка* описание = `[ряд, dx1, dx2]`. Обычная поза вниз
(индекс 8) — `$AF34`: ряд `+1`, точки `−6` и `+5`; вверх (индекс 9) — `$AF3A`:
ряд `−32`.

Точка отсчёта героя — **уровень ног**.

## 6. Чтение земли

`$AC35` (банк 9) читает тип поверхности в точке «герой + (dx, dy)»:
`$ABA6` складывает смещение с позицией, ограничивает Y видимой полосой
`$10..$AF` для горизонтальных зон, дальше `$F52C` в постоянном банке достаёт
байт типа. **Бит 7 = стена.** Остальные коды — в `pb2_collision.md`
(`01` лестница, `02` шипы, `04` поверхность воды, `05/06` течение, `87/88` лента).

Особый случай в `$AE69`: если под ногами `01` (лестница) и `Y & 0x0F < 8`,
игра смотрит ещё на 16 пикселей выше — так верх лестницы становится полом.

## 7. Подкат

Вниз + A из положения «присел» (`$9036`, f18=7, состояние `$10`, поза 13).
Измерено: 26 кадров, 60 пикселей — то есть около 2.3 пикселя за кадр.
Точные константы разбираются вместе с `$9036`.

## 8. Что ещё не разобрано

Лестница (`$9193`/`$91B5`), вода, урон и отбрасывание, конвейеры `87/88`,
удар (`$80` в состоянии) и бумеранг — следующий шаг Э2.
