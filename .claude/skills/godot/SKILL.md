# Godot в PB3

Движок: **Godot 4.6.1.stable.mono**, `/Applications/Godot_mono.app/Contents/MacOS/Godot`.
Проект: `game/`, точка входа `game/src/main.tscn` → `main.gd`.
Отрисовка: `gl_compatibility`, окно 256×240 растянуто целым числом, фильтр
текстур выключен (`default_texture_filter=0`) — иначе пиксели мылит.

## Запуск

```
GODOT=/Applications/Godot_mono.app/Contents/MacOS/Godot
$GODOT --headless --path game -- --replay=<файл.json>   # прогон записи
$GODOT --path game                                      # с окном
```

Аргументы после `--` достаются из `OS.get_cmdline_user_args()`.

## Новый скрипт с `class_name`

**Обязательно** после создания файла с `class_name` прогнать импорт:

```
$GODOT --headless --path game --import
```

Он заводит `src/<файл>.gd.uid` и вписывает класс в
`game/.godot/global_script_class_cache.cfg`. Без этого другие скрипты
не видят имя, `main.gd` не парсится, и **headless-Godot виснет молча,
без единой строчки вывода** — самая дорогая ошибка в этом проекте.
Руками кэш править не нужно, хотя и можно.

`global_script_class_cache.cfg` и `.uid` лежат в git — их надо коммитить.

## Правила движка

* **Никакой плавающей запятой в игровой логике.** Положение — в 1/256
  пикселя, скорость — в 1/256 пикселя за шаг. `int`, сдвиги, `>> 8`.
  Причина: сверка с картриджем идёт байт в байт, а `float` даёт разъезд
  на сотом шаге.
* **Шаг игры ≠ кадр картинки.** Один шаг двигает вид один раз и героя один
  раз. Подробности — `work/re/pb2_camera.md`.
* Данные — только из `game/data/`, который делают экстракторы в
  `work/extract/`. В коде движка не должно быть ни одной константы,
  списанной из ROM руками: константа приходит из JSON.
* Комментарий к коду называет адрес подпрограммы картриджа (`## $D3B8 --
  ...`), чтобы можно было вернуться к первоисточнику.

## Как доказывают, что сделано

Мнение не принимается. Принимается покадровая сверка:

```
python3 work/extract/verify_player.py --all-areas --random=12 --seed=59
```

Она играет сценарии кнопок на настоящем картридже через `work/tools/nesemu`,
потом те же сценарии в движке, и сравнивает каждое число. Один пиксель
расхождения — провал. Отдельный участок: `--areas=0:3`.

Разобрать одно расхождение: `work/extract/dump_diff.py`.

## Мусор

Инструменты пишут трассы в `$TMPDIR/pb2work` и убирают за собой сами
(`pb2_probe.scratch()` / `pb2_probe.sweep()`). Любой новый инструмент,
которому нужен временный каталог, берёт его оттуда же и в `finally` зовёт
`sweep` — трасса на 600 кадров весит десятки мегабайт, а прогон делает их
тысячами.

## Чего не делать

* Не редактировать `game/src`, `work/tools` и `work/extract`, пока идёт
  сверка: Godot перечитывает проект на каждом запуске.
* Не звать `Godot --headless` без `--path`: он возьмёт текущий каталог.

## Приёмка перенесённых NES-уровней: реальное прохождение

По запросу пользователя о проходимости вести `docs/qa/playthrough-checklist.md`:
отдельно Нова, Солбрайн и кооператив. Короткий запуск, проверка коллизий,
принудительный переход или тест с бессмертием не закрывают уровень.

1. Открыть штатный вход, выбрать одного героя. Смотреть игровой кадр,
   продвигаться обычными нажатиями до настоящего выхода/победы. Сохранять
   накопленную запись ввода, события перехода и кадры найденных проблем.
   `game/tests/playthrough.gd` позволяет подавать серии нажатий и смотреть
   результат; `start` явно начинает новый забег, `steps` продолжает текущий.
2. При застревании записать уровень, героя, координаты, нажатия, ожидаемое
   и наблюдаемое поведение. Для атаки проверять всю цепочку: попадание,
   потеря здоровья, смерть, анимация, исчезновение/предмет, освобождение слота.
3. Сверять поведение с ROM через локальный NES-эмулятор и дизассемблер.
   Для смешанной пары нет NES-оригинала: отдельно проверить родной алгоритм
   героя, родной алгоритм объекта и преобразование между ними. Решения о
   новых механиках не выдавать за поведение картриджа.
4. Исправить причину, воспроизвести участок, затем переиграть комнату
   от штатного входа. Сохранить запись успешного прохождения. Весь этап
   закрывать после непрерывной цепочки комнат и его босса.
5. Повторить другим героем, затем вдвоём. После общей правки перепройти
   затронутые ранее закрытые маршруты. В отчёте отделять пройденное от
   воспроизведённых дефектов и оставшихся непроверенными комнат.

Дифференциальный тест может ставить NES и Godot в одинаковое искусственное
начальное состояние ради изоляции ошибки. Это доказывает поведение модуля,
но не проходимость уровня. Подставлять результат такого теста в чек-лист
полных прохождений нельзя.
